用户看得到、点得动，但背后是空的或走不通的。按要紧程度排序，A3 涉及合规底线，最优先。

A3

监护人授权：确认闭环走不通，靠前端假装成功

合规底线
你看到
提交监护人邮箱后，点「模拟确认」按钮，状态变成「已授权」。
实际是
后端生成了确认 token 存进数据库，但 既不发送邮件、也不把 token 返回给前端（代码注释说「token 直接返回」，实际返回的是空响应——注释与行为不符）。真实的确认接口存在且能用，只是没有任何人能拿到 token。前端的「模拟确认」只是在浏览器本地改了个状态，刷新就失效。
为什么要紧
监护人授权是 PRD 8.1 的合规底线：授权失效时所有写接口 403，板块三的参与授权也跟着联动关闭。这条链路断了，等于合规机制只能演示、不能真用。
怎么办
开发期让 202 响应把 token 带回前端（与注释承诺一致，改动约几行），演示链路即通；正式上线前接 SMTP 真发邮件（见 B6）。
A2

Chat 页录错题：只存在你自己浏览器里

数据分裂
你看到
在 AI 辅导对话页（/chat）侧边栏录入了一道错题，保存成功。
实际是
这条错题只写进了浏览器的 localStorage，从未调用后端错题本接口。打开错题本页（/error-book）时，因为页面优先读后端数据，你在 Chat 录的这条根本不出现——两个页面各有一本互不相干的错题本。
怎么办
Chat 录入改走错题本真接口（POST /error-book 已就绪，前端 service 现成），低成本消除数据分裂。
A1

Chat 页 AI 回复：四条写好的话术在扮演 AI

演示壳
你看到
在对话页提问，1.5 秒后「AI」给出一段像样的回答。
实际是
前端按关键词匹配 4 条写死的回复（复合函数 / 错题解析 / 计划 / 数列求和），匹配不上就给一句默认话术，全程不接触任何后端和模型。回复里带「演示模式」标注，是明示的演示壳。
怎么办
接入后端对话能力前，该页只能定位为演示壳；短期保留「演示模式」标注即可，但 A2 必须先修（标注防误解，数据分裂防错误）。
A4

知识复盘「查看历史」接口：契约里有，后端没有

契约超前
你看到
接口文档（openapi）里定义了知识复盘的列表和详情查询接口。
实际是
后端只实现了「生成」，没实现「查询」。更隐蔽的坑：后端对未匹配的 /api/* GET 请求会返回前端首页 HTML（200 状态码），调用方拿到的不是 404 而是一个网页——排障时极易误判成「接口有响应」。
怎么办
从 summaries 表按 dimension='knowledge' 过滤即可实现，成本低；同时建议 SPA 回退路由只对非 /api 路径生效。
B

真代码，默认关着

这一档不需要改任何代码——实现是真的，只是默认配置下不生效。演示或验收前按下表逐项配好即可。

一句话记住：默认部署下，所有「AI 生成」的内容其实都是规则模板——建议、复盘、导学推荐、AI 调权，无一例外。
#功能默认状态（为什么不生效）怎么开启
B1 错题知识点向量匹配录入错题时自动推荐相关知识点 kb_embed_mode="off"，永远走关键词模糊匹配降级；向量索引目录为空 填 embedding API 的 key/地址/模型，切 api。智谱 embedding-3 已联调验证：4/4 查询 Top-1 命中
B2 知识图谱内容/knowledge 图谱视图 代码是真实实现，但数据库没跑过种子脚本时，图谱是空的 执行 scripts/seed_kb_math.py 等种子脚本
B3 LLM 生成建议 / 周复盘 / 导学推荐 llm_provider="mock"：MockProvider 永远返回空，全部走规则模板兜底（这是故意的多层兜底架构，不是 bug） 填 LLM 的 key/地址/模型，切换 provider。B4、B5 随此项一并生效
B4 AI 动态调权状态分权重随数据自动校准 触发链路是真的（提交学习记录后自动触发 + 手动端点），但因 B3 空转，调权永不执行，只留一行日志。另：PRD 说「每周批量」，实际是事件驱动，无独立定时调度 随 B3 生效；要不要补独立周调度是产品决策
B5 周复盘定时任务每周自动生成学科复盘 定时器是真的（每天 03:00 跑），但默认产出是模板复盘 随 B3 生效
B6 验证码邮件注册 / 找回密码 smtp_provider="real" 但账号密码为空，发送必然失败 配 SMTP 账号；团队测试可继续走 mock 验证码
C

故意留的兜底

断网、接口失败、数据不足时的降级设计，属正常工程实践。列出备查，只有 C7 有明确的上线前期限。

#项说明
C1OCR 拍照录入占位接口返回「功能未开放，请手动录入」，是 ADR 记录的故意降级。小瑕疵：注释说返回 501 与实际不符，且前端没人调用它（死端点）
C2错题本断网兜底后端不可达时退回 localStorage，注释明写「不静默」。与 A2 联动时会产生「Chat 录的错题只在本地」的假象
C3知识库硬编码树兜底接口失败时显示写死的演示知识树、不白屏。但没有「演示数据」标注，不如个人数据页的占位徽章规范
C4导学推荐冷启动阈值近 7 天不足 3 条记录时不给推荐，PRD 冷启动设计
C5个人数据页占位体系实时 → 缓存 → 占位数据三级降级，占位卡带徽章明示，是「不要静默 mock」的规范做法
C6各 service 缓存兜底网络不可达时展示上次成功的数据
C7匿名访问回落到演示用户不登录也能访问业务接口，数据全挂在固定用户 u_10237 下。MVP 演示期故意如此，上线前必须移除
✓

演示 / 验收前检查清单

按顺序过一遍，全部打勾后，演示看到的就是真实能力而非模板与占位。

  • A3 · 监护人 token 有送达通道先做最小改动：202 响应带回 token，演示链路即通；上线前再接 SMTP
  • A2 · Chat 错题录入走真接口消除 Chat 页与错题本页的数据分裂
  • B3 · LLM 切真实供应商建议、复盘、导学推荐才会出现非模板内容；B4/B5 随之生效
  • B1 · embedding 切 api 模式错题录入的知识点推荐走向量 Top-5，而非关键词碰运气
  • B2 · 知识库种子脚本已跑图谱视图有节点有边
  • B6 · 邮件通道可用SMTP 配好，或确认演示全程走 mock 验证码
  • C7 · 确认匿名 mock 用户的去留演示环境可保留；任何对外发布前必须移除
修复优先级（如需动代码，按此顺序投入最小、收益最大）
  1. A3 监护人确认闭环 — 合规底线，改动最小（响应带 token）。
  2. A2 Chat 错题录入走真接口 — 接口现成，消除数据分裂。
  3. A4 两条 GET 实现或契约降级 — 顺带把 SPA 回退收窄到非 /api 路径。
  4. B 级全部 — 不改代码，按上方清单配置即可。
