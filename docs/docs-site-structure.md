# 公开文档站结构（docs-site-structure）

> **版本**：v0.1 · 2026-09-29
> **性质**：**团队内部文档**（位于 `docs/` 下，**不对外发布**）。规定公开文档页（`/docs`）的章节骨架、页面模板、状态规则与措辞约束。
> **上游**：[visual-language.md](./visual-language.md)——视觉与文案真源；文档页属「内页」家族，适用 §8 产品内基础层。
> **范围**：**只定骨架，不含页面正文**。正文写在 `frontend/src/pages/Docs/content/`。
> 与 Skyer 于 2026-09-28 至 09-29 逐轮讨论确认。

---

## 0. 三条总规则

1. **公开文档与内部 `docs/` 严格分离**：内部 `docs/` 含契约、合规讨论、板块卡等内部信息，**永不公开**；对外只有 `pages/Docs/content/` 下的页面。
2. **只写现在真的能用的**（`status: implemented`）。开发中与占位的内容**不写**——写了就是谎。
3. **一页只讲一件事**。细致靠拆页，不靠写长页。

### 6.1 ⚠️ 本章硬约束（不可绕过）

- 支付整体推迟到 pilot 后（`pending-decisions` #30 渠道 / #7 充值入口 / #5b 付费条款）。
- **价格页**：只能写「pilot 封测期间免费，正式版定价方案待公布」。**不得出现任何价格数字，也不得编造订阅方案细节**——编一个方案就是编造。
- **计费页**：pilot 期间没有账单也没有支付 → 「封测期间不涉及账单与支付」。
- **一致性**：落地页顶栏「定价」标注为「暂无」，本章两页必须与其严格一致。一个说"暂无"、一个列方案，是最难看的自相矛盾。
- 顺序为 **Credits → 价格 → 计费**：先讲现在有的，再讲以后才有的，避免一进章就撞上两页占位。

## 9. 「致家长」页的内容骨架（特殊文档）

它不是操作说明，是**说明 + 承诺**，结构与其他页不同：

1. **EpochX 是什么**——一句话：记录学习状态的工具。**明确写"不是补课、不是提分工具"**（家长预期校准，这句放在最前）
2. **为什么需要您的授权**（<14 岁建档的要求，说人话）
3. **我们收集什么 / 不收集什么**
4. **数据不出境**
5. **没有排名，也不给孩子下评判**（状态是读数不是人格判定）
6. **AI 不会替孩子做决定**（每个动作都要孩子确认）
7. **您随时可以撤回**（撤回即删除）
8. **有问题怎么联系我们**（指向占位页）

- 与「监护人授权」页分工：**授权页 = 怎么操作**，**致家长 = 为什么 + 我们的承诺**，两页互链、不重复。
- 侧栏项加浅色 chip「家长」标识（不加色，只加标识，便于家长一眼找到入口）。

## 10. 页面模板

```markdown
---
title: 监护人授权
section: 开始使用
order: 6
status: implemented   # implemented | building | placeholder
updated: 2026-09-29
---

## 这是什么        ← 一两句，说清干嘛的，不吹
## 怎么用          ← 步骤 1-2-3
## 需要注意        ← 边界、限制、常见误解
## 常见问题        ← 本页相关，3 条以内
## 相关页
```

- **不保留 `owner` 字段**：面向用户的文档暴露内部分工无意义，且写在公开 content 里有外泄风险。
- `status: building` 的页**只保留 frontmatter + 「这是什么」一句**，写明"开发中，功能尚未开放"——**不写步骤**。
- `status: placeholder` 的页只有标题 + 占位块，按「不预先编造」规则。

## 11. 状态规则与侧栏呈现

| 状态 | 含义 | 能不能写内容 | 侧栏呈现 |
|---|---|---|---|
| `implemented` | 已实现 | ✅ 写 | 常规 |
| `building` | 开发中 | ❌ 不写（写了就是谎） | 灰色 + 「开发中」小标签 |
| `placeholder` | 占位 | ❌ 留空 | 虚线 + 灰色 |

`building` 页即使排在章首（如 AI 对话），也要显示「开发中」标签——**占位也要占得诚实**，避免访客以为点错或内容没加载。

## 12. 文件与路由落点

- **页面内容**：`frontend/src/pages/Docs/content/<section>/<slug>.md`（与落地页 `pages/Landing/content/` 对称）
- **路由**：`/docs`（索引）+ `/docs/:section/:slug`；落地页「资源」菜单三个链接（文档 / 更新日志 / 隐私政策）指向对应页
- **排序**：由 frontmatter `order` 字段控制，**不用文件名编号**——以后中间插新页不用全量重命名
- **渲染**：`react-markdown` 已在依赖中；视觉走 visual-language §8 产品内基础层（纸感 + hairline + 语义 token + 长文衬线），**无大光、无 WebGL**；**度量与排版细节见 §8.4 文档页视觉定档**（圆角 / 间距 / 字号 / 行宽 / 提示卡 / 侧栏 / 深色 / 可复用组件）

## 13. 维护规则

1. **新增页**：在骨架表中登记 → 建 `content/<section>/<slug>.md` → 填 frontmatter（`order` 用间隔值，如 10/20/30，便于插入）
2. **状态变更**：功能落地时 `building → implemented` 并补写内容；**不得反向**（已写内容的功能若回退，状态改回 building 并删掉步骤）
3. **一致性检查**（每次改动都过一遍）：
   - 价格 / 计费页措辞 ↔ 落地页「定价 = 暂无」
   - 隐私与安全章 ↔ 落地页信任屏四条
   - 任何新文案 ↔ visual-language §6 文案红线（禁打鸡血词、好评判也是评判）
4. **不预先编造**：联系方式、协议链接、备案、价格等一律留空占位。

**⚠️ 顺带发现并已修复一处阻塞级缺陷**

新迁移 **`a91f4c2d7e03`（A 板块 M1 · 出生年份 + #29b 开关）在非空库上必然失败**。受控复现（临时库，未碰开发库）：

```
[空库]   settings 0 行 -> upgrade head 成功
[非空库] settings 1 行 -> upgrade head 失败
         sqlite3.IntegrityError: NOT NULL constraint failed:
         _alembic_tmp_settings.experience_improvement_enabled
```

根因：迁移第 40–48 行在**同一个** `batch_alter_table` 里先加 `NOT NULL` 列（带 `server_default='0'`）、
紧接着 `alter_column(server_default=None)`。SQLite 的 batch 模式是「建临时表 → `INSERT INTO tmp SELECT ...`
（**该 INSERT 不含新列**）→ 删旧表 → 改名」。`server_default` 已被摘掉、新列又不在 INSERT 列表里，
于是存量行拿到 `NULL` → 违反 NOT NULL。**空库时 `INSERT` 插入 0 行、不触发约束，所以能过。**

- 因此**「空库 `upgrade head` 通过」这道验收门抓不到它**，与之前「本地库落后一迁移」「pytest 抓不到」同属一类陷阱：
  **验证路径没覆盖真实故障条件**。只验空库的护栏等于没有护栏。
- 失败后 `data.db` 会停在**半迁移态**：SQLite DDL 非事务，`users.birth_year` 已落、版本号未前进，
  重跑会再撞 `duplicate column`。恢复办法是从备份还原。
- **影响面**：任何已产生过 `settings` 行的库（本地开发库、已放量的 Neon）升级都会失败。

**已修复**（2026-10-01，本机 agent 持 X0 权限，见 `AGENTS.md` §〇）：拆成**两个** batch ——
阶段 1 保留 `server_default='0'` 让重建出的临时表带默认值兜住存量行，阶段 2 再单独摘默认值
（此时该列已在 `settings`，重建时的 INSERT 会带上真实值）。revision id 未改。

新增 `backend/tests/test_migration_nonempty_db.py`（7 例）作**空库 + 非空库双向**回归护栏，
并做了 tamper 验证：改回「同一个 batch」后**恰好 3 条非空库用例失败、4 条空库用例仍通过**——
精确复现了当初漏掉的原因，恢复后 7/7 通过。
