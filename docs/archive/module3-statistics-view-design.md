## 定位

板块三的合规形态是「匿名统计视图层」：独立于板块一/二原始表，
只下发**服务端聚合后的统计量**（分位数、直方图桶、规模），
绝不下发任何他人个体特征或原文。

## 原则

1. **匿名化在源头**：上传即匿名特征值，不含可关联身份字段。
2. **最小群体规模**：任何聚合结果仅在样本 ≥ k（建议 k≥20）时返回；
   低于 k 返回 `COMMUNITY_INSUFFICIENT_POOL`，防小样本反推个体。
3. **只发聚合不发个体**：`/community/aggregate` 只返回分位数 + 直方图桶，
   前端不得再按个体数据本地计算（现有 Compare.tsx 是演示雏形，需改写）。
4. **显式授权**：用户必须先主动开启 `communityConsent`，可随时撤回；
   撤回后其历史特征不再参与后续聚合。
5. **禁止上传黑名单**：原始学习内容、错题原文、自评文本一律禁传。

## 数据流（预留）

```
板块一/二数据（明文，库内）
  → 特征抽取（状态分/掌握度/时长，不含原文）
  → 脱敏/分桶 → community_features（特征值表，不含 user_id）
  → 聚合视图（按 subject/metric 预计算分位数）
  → GET /community/aggregate?subject=&metric=  下发
```

## 契约预留（openapi.yaml x-status: planned，不实现）

- `POST /community/features`：匿名特征值上传（显式授权后）
- `GET  /community/aggregate?subject=&metric=`：聚合统计（含最小规模校验）
- `GET /me/community-consent` / `PUT /me/community-consent`：授权查询/开关

## 风险与隐私评审点（计划书 3-C）

- 反推风险评估：k 值、分桶宽度与差分噪声是否引入，由**团队内部自查**定（〔pilot 口径〕降级项：原为「需隐私工程评审」；差分隐私记入待办，不阻塞）。
- 未成年人场景（PRD 8.1）：「匿名」对个体可识别性不构成免责，
  授权仍需监护人授权链路一致。
- 演示页误认风险：已加「演示数据」水印（3-A）。

## 结论

本设计不动代码；正式立项（真实上传 + 服务端聚合）须在板块二 MVP
数据验证后单独立项，并先完成**团队内部隐私自查**并留书面记录（〔pilot 口径〕降级项：原为「先过隐私工程评审」，PRD 10.2 明示为上线前置条件；外部隐私评审签字记入待办，不阻塞）。
