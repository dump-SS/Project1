## 1. 逐步实测

### Step 1 注册（UI 全流程）✅
- 操作：`/register` 填邀请码 `EPX-W279-YJJW` + 邮箱 + 密码 → 「获取验证码」→ 从后端日志取码

  - `POST /api/v1/auth/register → 201 Created`

### Step 2 登录（密码）✅

### Step 3 Chat 一轮（真实 LLM）✅ —— 但发现 P1（见 §2.2）
- 操作：`/chat` 输入「用一句话说明什么是二次函数的顶点式」→ 发送。发出时刻 `23:23:46`（本地）。

- ⚠️ **辅助留痕丢了两条**（详见 §2.2）：`ai_call_logs` 0 行、真实用量行（3759/173 tokens，¥0.008902）被回滚。

### Step 4 拍题（图片上传）⚠️ 降级路径 ✅
- 方法说明：IAB 不支持原生文件选择器（`filechooser` 能力不支持），用页面内
  `DataTransfer` 构造 1×1 PNG 注入 `<input type=file>` 并派发 `change`——
  **走的是真实 UI 事件链与真实上传请求**，不是绕过 UI 直接 fetch。
- UI 实际反馈：拍题面板弹出红色提示 **「上传失败：对象存储未配置，请联系管理员」**（本机无 R2 凭据，预期降级）。
- 后端实际响应：`POST /api/v1/f/media → 503 Service Unavailable`
  `{"error":{"code":"R2_NOT_CONFIGURED","message":"对象存储未配置，请联系管理员"}}`。
- 结论：上传链路前端→代理→后端→R2 配置检查→错误呈现，全链真实走通；「R2 未配置」的降级表现见
  降级矩阵文档 D5。

### Step 5 计划/计时 ❌ —— **发现 P0（见 §2.1）**

- 实际：跳 `/study-timer?minutes=40&planId=p_cfa6ce5f2105&subject=SX` 后**整页白屏**（`#root` 空、readyState=complete）。

## 2. E2E 抓出的两个真问题

### 2.1 🔴 P0：登录用户进计时页整页白屏（`/study-timer`）
- 错误（浏览器捕获）：`Uncaught ReferenceError: floatOpen is not defined`，渲染期抛出 → React 卸载整树。
- 定位：`frontend/src/pages/StudyTimer/index.jsx:987-988` 引用 `floatOpen` / `setFloatOpen`，
  **整个文件没有任何 useState 声明它们**。引入提交：`d2f3b78`（[Chat] 交付 Chat 内核真链路…划选浮窗…）。
- 影响：**所有登录用户**进计时页即白屏（游客态走 `GuestTimer` 不受影响）——计时/学习记录主链路对已登录用户全断。
- 为什么既有测试没抓到：pytest 是后端；前端 vitest 只覆盖 `services/chat` 与 `pendingHint`，没有页面级挂载测试。
- **修复建议（一行）**：在 `AuthedStudyTimer` 中补 `const [floatOpen, setFloatOpen] = useState(false)`。
  本单按「验收不改代码」边界**未修**，请裁定派给 C 板块负责人或授权我随手修。

### 2.2 🟠 P1：慢 LLM 调用期间，辅助写会话拿不到 SQLite 写锁 → 留痕与真实用量静默丢失
- 现场（`backend.log`，本轮 E2E 真实一次调用）：
  ```
  23:24:15.272  INSERT INTO ai_call_logs ... ('acl_99b19cf14236','chat','state_plan',None,3545,1,0,None,None)
  （无 COMMIT）
  23:24:20.760  ROLLBACK                                   ← 5.5s ≈ busy timeout
  [usage_ledger] 模型 Step-3.5-Flash 未登记计价，按兜底单价 (2.0, 8.0) 计入
  23:24:20.763  INSERT INTO usage_ledger ... (3759, 173, 0.008902)   ← 真实用量
  （无 COMMIT）
  23:24:26.322  ROLLBACK                                   ← 又 5.6s
  23:24:26.324  INSERT INTO chat_raw_messages ...（成功）
  23:24:26.327  INSERT INTO usage_ledger ... (6, 15, 0.0)  ← len//4 估算兜底行
  23:24:26.328  COMMIT
  ```
- 终态（sqlite 实测计数）：`ai_call_logs = 0 行`（PRD 6.5 留痕整段丢失）、
  `usage_ledger` 只剩估算行（6/15 tokens、cost 0.0），**真实用量行（3759/173、¥0.0089）丢了**。
  写入失败在 `ai_call_log._persist` 里被 `except: logger.debug` 吞掉——**INFO 级日志完全不可见**。
- 隔离证明（降级矩阵 A13）：把 LLM 切成 **mock（毫秒级快调用）后，`ai_call_logs` 5/5 全部落库成功**
  ——说明写入器本身没坏；丢失只发生在「真实 provider 慢调用」窗口期，指向**并发写锁竞争**。
- 影响：pilot 铁律 5「按用户记录数值成本」在慢调用场景**失真**（用户看到 0.00，真实 0.0089）；
  LLM 调用留痕缺失影响问题回溯。
- 说明：Postgres/Neon 是行级锁 + MVCC，**大概率不复现**；本结论仅对 SQLite 运行时成立，需在 Neon 上复核。
- **修复方向（供裁定，本次未改代码）**：辅助写改用请求 session（随主事务提交）/ 开 WAL / 写失败升级为
  WARNING 并重试一次；任选其一都能把「静默丢」变「要么在、要么喊出来」。
