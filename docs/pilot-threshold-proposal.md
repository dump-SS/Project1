## 1. 逐项建议

### 1.1-1 激活率 ≥ 70% —— ✅ 保留，但把分母写死

**建议**：数值不动，**补一句分母定义**：分母 =「注册成功且至少登录过一次」的用户数，分子 = 该批用户中 `users.onboarding_completed = true` 的比例。

**依据**：邀请码是定向发放的（`scripts/gen_invite_codes.py`，默认 10 个/批），受邀者动机本就高于自然注册，70% 对定向样本不算激进。风险可控。

**必须写清的原因**：分母里如果混入「注册后从未登录」的用户（典型是家长被叫去授权但孩子没跟进），激活率会被系统性压低，而**低龄用户恰恰必须走监护人授权**（未满 14 岁）——这批人最容易被算成"没激活"，指标会冤枉合规流程。

### 1.1-2 次周留存 ≥ 25% —— ⚠️ 建议降为观察项

**建议**：pilot 期**先不设硬阈值**，作为观察项记录；等通知能力（站内通知 / 邮件提醒）就位后再定线。

**依据（这是最关键的一条）**：
- 「第 7 天仍有记录或对话」要求用户**主动回来**。产品当前**没有已确认的推送触达能力**——`getting-started` 与 `account/notifications` 页状态仍是待确认（后端有 SMTP，前端是否有设置项未核实）。**没有提醒，用户不回来是正常的**，25% 这条线在当前能力下测的是"学生有多自觉"，不是"产品做得好不好"。
- 样本量也不支撑（见 §3）。

**如果一定要现在定**：建议 15%，并明确写"该值在通知能力就位后重估"。低于 20% 不宜判 pilot 失败。

### 1.1-3 首日闭环完成率 ≥ 40% —— ✅ 保留，标注前置

**建议**：数值不动，**加前置标注**：C 板块（计划 / 计时 / 记录）目前**后端地基已并入 main，前端壳与受限 Chat 未完成**。此项在 C 前端落地前**读不出完整数据**（plans 有、timer_sessions 有、learning_records 有，但用户走不完界面上的整条路）。

**依据**：40% 对"新用户首日走完一个完整学习闭环"是合理预期（引导成本不低）。此值一旦可读，对产品价值判断的权重最高，建议作为**主指标**而非与激活率并列。

### 1.2-1 报错率 ≤ 5% —— ✅ 保留，另加会话级硬信号

**建议**：数值不动，**新增一条**：

> **会话级失败率 ≤ 2%** = 单个会话内出现 ≥2 条消息级 error_report 的会话数 / 总会话数

**依据**：总量口径会掩盖集中故障——绝大多数会话顺利、少数会话整段崩坏时，报错率可能只有 2%（合格），但用户体验已经崩了。会话级口径能把这种"集中失败"抓出来，两者取**更严的**判定。

**口径说明（要写进基线）**：messageId 为空的报错（设置页常驻入口）**不计入**分子——那是用户主动反馈，不等于模型输出失败。

### 1.2-2 反馈有用率 ≥ 60% —— ✅ 保留，加口径说明

**建议**：数值不动，补一句：**分母仅为实际提交过反馈的用户**，且此指标**自选择偏差显著**（愿意点反馈的用户本身倾向更满意），因此只作**趋势观察**，不作为 pilot 成败的判定项。

**依据**：现有 feedback 接口覆盖 assessments / recommendations / summaries 三处，样本天然偏小。

### 1.2-3 / 1.2-4 卡片点击率 ≥ 30%、意图纠正率 ≤ 10% —— ⏸ 暂不拍

**建议**：**这两项现在不拍板**，等 B 板块真链路 + 前端埋点接线后再定。理由：

- Chat 页目前仍是 `setTimeout + 关键词匹配` 的前端 mock，**`backend/routes/chat.py` 根本不存在**（main 上 22 个 router 无 chat）；
- `analytics_events(chat_interaction)` 的**前端调用点为零**（只有埋点接口本身通了）；
- 试点 1（§4）里这两项都读不出来。**在分母为 0 的指标上写阈值，等于写一句没有依据的话。**

**建议在基线里改为**：`pilot 二期（B 完工后）评估是否设阈值；pilot 一期仅记录原始数值，不设判定线`。

### 1.2-5 危机响应触发正确率 100% —— ✅ 保留为红线，补建评审机制

**建议**：数值不动（这是底线不是目标），**但必须在基线里写清怎么验**：现写法是"人工评审抽样"，而**抽样名单、评审人、记录格式目前都不存在**。

**建议的最小机制**（M6 前落地，不需要工具支撑）：每个 pilot 用户首次真实对话后，由 G 板块按固定脚本试跑 5 个应转介场景，评审结果记入一张表，**红线判定 = 5/5 命中 L3 固定文案**。

**依据**：这是全表唯一的 100% 项，且是安全底线——**5% 的转介漏检在未成年人场景不可接受**。但没有机制的 100% 等于没有。

### 1.3 画像改删率 ≤ 30% —— ⚠️ 建议降为观察项

**建议**：pilot 期作为观察项，不设判定线。**原 30% 这个数是拍的**，没有依据；且画像提取功能尚未接线，现在也读不出。

**依据**：这个指标的设计意图（改删率高 = 提取质量不可信）成立，但阈值需要**先看一轮真实分布**再定。定一个无依据的数，只会在第一期数据出来后显得"好像不达标"，实际是标准本身没有依据。

### 1.4 三项成本 —— ✅ 保留观察项，加记录义务

**建议**：三项（单用户月成本 / 档位成本结构 / embedded 占比）**继续作观察项**，但补一条：

> **pilot 结束前必须产出第一版实际成本数据**，作为 beta 定价评估的输入。**不在 pilot 期设成本红线。**

**依据**：`usage_ledger` 计价表已实心（`069d896` 走环境变量，不空心），数据可采集；但**当前没有任何真实调用样本**（Chat 未完工）。现在拍成本阈值等于凭空设限。

### 2.2 5xx ≤ 1% —— ⚠️ 数值保留，三处口径要改

**建议**：数值 1% 保留，但基线要改三处：

1. **时限从「连续 4 周」改为「pilot 正式放号之日起连续 4 周」**。现在 B/C/E 都没完工，从现在起算 4 周毫无意义。
2. **分母口径写死**：仅统计 **API 请求**（`/api/v1/**`），**排除 4xx**（4xx 是客户端行为，与服务稳定性无关）、**排除 `/health`** 健康检查（它本就该常 200，但被刷会稀释分母）、排除静态资源。
3. **⚠️ 前置缺失（这条最重要）**：项目**当前没有任何 5xx 监控设施**——只有 `backend/routes/health.py` 一个健康端点，无 Prometheus / Sentry / 日志聚合。**"5xx 率"现在无法自动读出**，只能靠翻日志。

**建议**：把「接入最小可用的错误计数」列入 pilot 一期的 G 板块任务（哪怕只是 `analytics_events(category='quality')` 埋一条 5xx 事件，或 FastAPI 中间件计数 + 定期落库），否则 §2.2 是一张**永远无法验证的验收门**。

### 2.4 样本充分：累计激活 ≥ 50 —— ⚠️ 建议分两期

**建议**：改为**两期**，并把合规成本写进这条：

| 期 | 规模 | 目的 |
|---|---|---|
| **pilot 一期** | **20 人** | 跑通全链路 + 埋点 + 5xx 可观测性；不发大规模邀请 |
| **pilot 二期** | 扩至 **50 人** | 指标覆盖一个完整月，评估 §1.1 各阈值 |

**依据**：
- 邀请码脚本默认批量 10 个 → 20 人 = 2 批，50 人 = 5 批，节奏可控；
- **更重要的成本项**：50 人里若含较多初中生，**监护人授权要走 40–50 次**（A 板块刚落地：低龄需确认、无响应则建档卡住）。这是**运营主工作量**，不是技术问题，必须提前算进排期，否则会卡在"码发出去了但人进不来"。

**关于 n=50 的判定力**：见 §3——50 的样本量**不足以判定 25% 这类阈值**。

## 2. 建议新增的项（原基线没有，但 pilot 期必须看）

**2.A 监护人授权流程成功率 = 100%**

- 定义：低龄用户提交授权后，监护人点开确认链接成功完成确认的比例
- 理由：这是**合规关键路径**且刚落地（A 板块 M1），"点不开"或"链接失效"会直接卡住低龄用户的建档；且是家长与产品的**第一次接触**，体验权重高
- 现状：确认结果页刚上线，尚无数据

**2.B 邀请码核销率 ≥ 80%**

- 定义：`used_by` 非空的邀请码 / 已发放邀请码
- 理由：名额制发放最容易出的问题是"码发出去没人用"——说明投放对象选错，或注册流程劝退。这条比激活率更早发现问题

**2.C 首次会话中断率 ≤ 15%**

- 定义：创建会话后未产生任何 message_sent 就离开的会话 / 总会话
- 理由：Chat 是首页，第一句话说不下去就走了，是产品价值的直接流失点。（此项依赖 B，一期读不出）

## 3. 样本量与判定精度：n=50 不足以判定硬阈值

这是本稿最需要你注意的一条。以下按二项分布标准误估算（pilot 激活率按 70%、次周留存按 25% 计）：

| 样本量 | 激活率 95% 置信区间 | 次周留存 95% 置信区间 | 判定力 |
|---|---|---|---|
| 20（一期） | ±19pp | ±19pp | 只能看趋势 |
| **50（二期）** | **±12.7pp** | **±12.2pp** | 只能看趋势 |
| 100 | ±9pp | ±8.6pp | 可勉强判定 |
| 200 | ±6.4pp | ±6.1pp | 可判定 |

**结论**：n=50 时，观察到的 25% 留存率的真值区间是 **13%–37%**——**"25%"和"15%"在统计上区分不开**。同理 70% 激活率与 58% 也区分不开。

**两条推论**：
1. **n=50 阶段，§1.1 各项只能作观察项**，不作为 pilot 成败判定；判定留到 n ≥ 100（若 pilot 规模能达到）。
2. 若一定要在 n=50 时保留判定线，建议改成**区间判定**：如"激活率落在 55%–85% 区间内视为波动，不判定；连续两期低于 55% 才判不达标"。
