## 0. 一句话核心转变

从「**页面 + 导航**」的产品结构，转向「**对话为核（首页 Chat）+ 个人中心为仓**」的双柱结构。

- **Chat = 行动与对话的起点**：一切动作（闲聊 / 建任务 / 搜题 / 复盘）从对话发起。
- **个人中心 = 关于我的一切**：数据、画像、档案、复盘记录、目标树详情、社区参照。
- 其余功能退化为「少数独立页 + 侧面板」的辅助形态。

由此，项目的**交互核心从「逐页点导航」变为「对话驱动 + 上下文栈」**。

## 1. 入口与身份

### 1.1 免登录 / 游客双轨 ✅
- **不强制登录**。游客可**试用**（创建计划、计时等），但：
  - ❌ 不保存任何用户数据；
  - ❌ 不提供 AI 能力；
  - 只能用**纯表单**完成操作，**不能用 Chat**。
- 游客身份区显示「游客」+「?」，悬停提示：`当前登录状态不可使用 AI 功能，用户信息不保存，您可以试用 xxx 功能…`
- 页面中涉及 AI 的功能对游客**标灰 / 虚化**，并配小字引导。

**游客的「出口」（登录入口常驻）** ✅：

- 点身份区「游客 ?」**展开即登录 / 注册入口**——游客在任何页面都能随时转登录，不需要先回首页或先退出。
- **试用数据不接管**：游客期间创建的计划 / 计时记录，在登录或注册成功后**不迁移、直接清空**（沿用上方"不保存任何用户数据"口径）。
- 转登录**不额外弹确认**：既然口径是"不保存"，就没有"你会丢失什么"需要告知；清爽切换即可。
- ⚠️ 实施前提：需先解决匿名会话归属——现状后端 `current_user` 在无 sid 时兜底为共享用户 `u_10237`，游客态真落地前必须让游客数据既不落库也不串到别人账上。

### 1.2 首次体验 ✅
- 首次进入显示登录页：**登录 / 注册**两个形态。
- 登录 → 播放入场动画 A → 进入首页。
- 注册形态有「**暂不登录，先试试看**」按钮 → 播放**另一入场动画 B** → 以游客身份进入首页。
- 完成注册登录的**合法新用户**首次进入，走「激活式引导流程」（类似系统激活页），含**建档 + 个性化**，完成后衔接动画进入首页。

### 1.3 第一天体验与新手引导 ✅

**目标**：让新用户跑通第一个闭环「计划 → 计时 → 记录 → 状态+建议」，制造 Aha moment；不灌输功能。

**新手任务（软引导）** ✅：
- 首日推荐区 Go on 组为空，让位「新手任务：创建第一个学习计划」；
- **软引导**，可自由跳过；完成后自动消失，让位正常三组。

**空态问候语（Chat 上方）** ✅（预设骨架 + 动态填充的混合）：

- **预设骨架**：每次进入首页的**冷启动时刻先展示**（按时段切换的固定文案，如"晚上好，今晚想学点什么"）。
- **有画像后**：骨架展示片刻 → **逐字退格**删去 → **逐字输入**动态个性化内容（如"今晚想继续复习几何吗？最近 3 次练习都涉及它"）。
- **新用户（无画像）**：仅展示预设骨架，**无退格/重打过渡**（无动态内容可切）。
- **不逐次烧 LLM 生成问候语**（骨架预设、变量由画像即时填充）。
- 骨架停留时长（约 1–1.5s）实现时定。

**渐进揭示** ✅：
- **按需引导为主**：用户点到哪页，该页首次进入给轻引导（各页自带首次提示）；
- **功能引导演示卡为辅**：首页首次放一张「功能引导演示」卡，用户可选点击，走预设"逐页讲解"流程（一次性）；
- **不做按时间逐个推荐**。

## 2. 信息架构（IA）

```
【入口】
登录 / 注册 / 游客(试用)
 ├─ 首登 → 激活式引导(建档＋个性化) → 动画 A → 首页
 └─ 游客 → 动画 B → 首页(游客态，AI 灰)

【首页 = Chat】(主焦点)
 ├─ 上方：问候语 / 文字提示
 ├─ 下方：推荐卡片(建议)
 ├─ 中央：对话流 + 输入（单线程 · **无历史列表**，见 §3.8）
 └─ 侧面板(视觉弱)：搜题结果 / 任务卡 / 复盘 / 目标树简略

【独立页】(导航视觉弱化)
 ├─ 计划  guide
 ├─ 计时  全屏沉浸 · 可呼侧栏 Chat(知识求助)
 ├─ 个人中心  (数据总览＋画像＋档案＋复盘记录＋目标树详情＋社区参照＋收藏＋设置)
 │    └─ 设置 ─┬─ 账号与资料(建档 / 登出)
 │             └─ 授权与隐私(监护人授权 · AI 三开关 · 匿名群体参照)    ← 见 §4.7
 ├─ 知识   (掌握度总览＋检索＋详情＋题本＋搜题/讲解归档＋图谱＋难度双层＋考试)  ← 见 §4.8/§4.9
 └─ 目标 goals → ❌ 已取消独立页，并入个人中心

【共享逻辑】
 ├─ 目标树：长期目标 → 多个短期子目标(父子)
 ├─ 复盘  ：chat 侧面板生成 ＋ 个人中心记录(可一键复盘)
 └─ 计时知识求助：临时会话 → 自动归档
```

## 3. 核心交互逻辑

### 3.1 首页 Chat：意图判定三分类 ✅
用户输入后，模型判定意图：

| 意图 | 回应方式 |
|---|---|
| **闲聊** | 基于**用户画像**（成绩 + 兴趣/性格/经历）恰当回应；过程中**适时提取关键信息写入画像** |
| **创建任务** | 自然语言 → 结构化**任务卡**，随对话输出；信息不完整时追问补充；卡内可交互；能识别「预习/复习 X」类**学习请求**，自动关联知识点 + 建议时长 |
| **知识求助** | 三分支（斜杠前缀区分）：**/搜题**（解一道题）、**/讲知识点**（讲透概念）、**/查**（查概念/公式/定义）|

- 意图判定入口：**斜杠命令 + 按钮 + 模型裸判** 三者并存。✅

**三分类的正确读法（重要澄清）** ✅：三分类是**意图识别口径**，**不是「输出只能一种」的限制**。

用户一条消息常常杂揉多个意图（"这道题不会，顺便帮我定个今晚的计划"）。处理原则：

- **主意图决定回应基调**（先讲题还是先建计划，决定语气与组织方式）；
- **允许多产物**——同一轮里同时输出任务卡 + 知识点卡片完全没问题，产物本就是结构化 payload（D22）；
- **不强行三选一**，否则会把用户的复合诉求砍掉一半。

**跨场景引导原则：先当人，再当助手** ✅

典型场景：用户倾诉学习困境（"我就是管不住自己"），表面像闲聊、实质是学习问题。

- 判定为**闲聊**（不是建任务），回应姿态是共情 + 追问；
- **不主动推销功能**——不在用户还在倾诉时就跳出来"要不要建个目标"；
- 等用户给出**"我想改"的信号**后，再提议建目标（走任务卡）；
- 例外：用户明说"我想改 / 帮我想想办法"时，可立刻提议。
- 斜杠前缀按意图细分：知识求助下有 `/搜题` `/讲知识点` `/查` 等，可扩展、供用户选择。🟡

**首页推荐卡片（空态引导）** ✅

定位：Chat 空态下的「可点击对话起点」——卡片点击与「斜杠命令/前缀」**同源**，都是把意图结构化递给用户。

**三组精简分组**（横向滚动，组标题分隔）：

| 组 | 内容 |
|---|---|
| **Go on**（继续） | 未完成计划/任务、未回填正确率提醒、待续复盘 |
| **推荐** | 状态 / 内容 / 目标规划 三类建议合并，卡内用**标签/颜色/背景**区分类型 |
| **洞察** | 群体洞察（L4，带"N 名匿名同龄人"标注）|

- **快捷动作不再占推荐区**：仅**游客态**在推荐区展示；登录用户统一收进输入框「**+**」菜单。

**「+」菜单与自定义常用语** ✅

「+」菜单容纳三类：① 内置斜杠前缀（/搜题 等系统意图）；② 快捷动作（开始计时 / 搜题 / 建计划 / 建目标）；③ 用户自定义常用语。

自定义常用语**两种形态（都要）**：
- **纯文本快捷语**：一段固定文字，点击即填入/发送（如"帮我复盘今天的学习"）。
- **固化 prompt（可带前缀）**：把带意图前缀的提示固化，点击即以该前缀+内容发起（如"/任务 每天背 20 个单词并打卡"）；前缀可用系统内置，**也可用户自定义**。

常用语支持**用户自定义分组**：用户自建分类（如「计划 / 闲聊 / 复盘」），组内多条。

**卡片两层结构（关键机制）**：每张卡 = 展示层 + 意图层，点击注入结构化 payload，而非拼字符串。

```
卡片 = {
  type:    "content_advice",        // 类型决定卡面标签/颜色/背景
  display: { title, subtitle },     // 展示层（用户看到的卡面）
  payload: {                        // 意图层（点击注入对话）
    refs:       { pointIds, subject, planId? },  // 实体引用（精确）
    generated:  { 结论, 依据 },                    // 已生成摘要
    instruction: "..."                             // 给模型的任务指令
  }
}
```

**逐类卡片的输出内容 + payload**：

| 卡片 | 卡面 display | payload 注入 |
|---|---|---|
| 继续计划 | "继续今晚数学 · 完成 2/6 · 剩 25min" | refs=planId；instruction=基于计划现状继续 |
| 状态建议 | "你数学有点疲劳 · 今晚建议减量" | refs=stateLabel/trend/历史；generated=建议摘要；instruction=展开成具体可执行建议 |
| 内容建议 | "推荐复习：函数单调性" | refs=subject/pointIds；generated=依据("近3次错题卡这")；instruction=解释为什么+怎么做 |
| 目标规划 | "为长期目标拆出下周 3 步" | refs=goalId/目标树；generated=差距；instruction=规划拆解 |
| 群体洞察 | "同节奏人群本周普遍减量" | refs=维度/分位；generated=数据+N 名匿名同龄人；instruction=解释+我该怎么办 |

**两阶段**：
- **生成阶段**：后台（规则 + AI）产出候选卡（display+payload），排序、去重、抑制重复。
- **点击阶段**：payload 作为结构化上下文注入对话，模型据此生成回应。

**为什么结构化 payload 而非拼字符串**：① 精确（实体引用不靠猜）；② 可复现/可追溯；③ 可降级（游客/无 AI 时规则模板能读 structured 指令兜底）。

**生成规则（出现 → 排序 → 重复抑制）** ✅

原则：空态卡片是"降噪"，**宁缺毋滥**——没有足够好的卡宁可少推。

| 组 | 触发条件 | 组内排序 | 去重指纹 | 冷却 |
|---|---|---|---|---|
| Go on | 存在未完成事项即硬性出现 | 按逾期/紧急度 | planId/recordId | 划掉后 3 天不推 |
| 推荐 | 需 AI + 足够数据；不足整组空缺 | 状态 > 内容 > 目标规划（时效）| type+pointId/subject | 7 天不重复，只推"有变化"的 |
| 洞察 | 需社区聚合 + 匿名样本；克制出现 | 相关度，≤1 条 | 维度+周期 | 每周 ≤1，同维度周内不重复 |

- **组顺序固定**：Go on → 推荐 → 洞察（横向滚动从左到右）。

### 3.2 任务卡 ✅
- 结构：由自然语言抽取的关键信息（学科/主题/时间/目标等）。
- 交互：**卡内可直接操作**（勾选完成 / 改时间 / 删除）。
- 位置：既输出到**对话流**，也可进入**侧面板**。
- 切页顺承：用户在对话里未建完任务 → 前往手动**计划/目标创建页**时，模型输出的任务信息**顺承到创建页**，有「是否保留」选项。

### 3.3 任务实体归属 ✅
- 沿用现有两套逻辑：**计划（guide）** 与 **目标（goals）**。
- 目标新增：**长期 / 短期目标有从属（父子）关系**；模型具备**规划长短期目标**的能力（这本身算一类建议）。

### 3.4 上下文栈 ✅（单对话 + 上下文）

- 采用**单会话 + 上下文栈**模型（非多线程并行会话）。
- 支持中途切换：闲聊一半去搜题、任务没建完去闲聊，模型需做出对应反应、输出与调整，并记住未完成事项。

**拆两层（关键）**：

| | 上下文栈 | 持久化中间态 |
|---|---|---|
| 管什么 | 对话**进行到一半**的瞬时状态 | 未完成的**实体**（任务草稿/未回填记录/待续复盘）|
| 存哪 | 会话内（临时）| 落库 |
| 生命周期 | 随会话（边界见 §3.8.1）| 有各自 TTL |

**栈三规则（默认值）**：
- **深度 = 3**：最多挂 3 个"聊到一半"分支；超过则最旧者**沉降**（按类型分流，不丢）。
- **过期**：栈内上下文**随会话老化失效**（会话 = 连续使用周期，不活跃超阈值即老化，见 §3.8.1）；沉降物各有 TTL——任务草稿「7 天不碰 → 归档/提示」、未回填记录「永不强制、不再主动提醒」。
- **优先级 = LIFO**（后进先出）：栈顶 = 最近切走的事，切回优先接续；不做复杂优先级（重要的未完成事由 Go on 组持久化浮出）。

**沉降分流（超限时按类型）**：
- 任务草稿 → 转持久化中间态（进 Go on 组）；
- 搜题/讲解到一半 → 转知识页归档（可重新发起）；
- 纯闲聊中断 → 直接丢弃。

**与锚定卡 / Go on 的关系**：栈顶瞬时接续走「锚定确认卡」(§3.7c)；跨会话长期未完成走「Go on」推荐组——一个管"秒级接续"、一个管"天级续命"。

### 3.5 知识求助：搜题（解题）+ 知识点讲解 ✅

**五阶段链路：**

```
① 输入与识别   题面进来 → 识别 科目/题型/涉及知识点
② 解题生成     AI 分步解题（检索增强后置）
③ 解析呈现     侧栏结构化展示（卡片式）
④ 知识关联     知识点查询（embedding）→ 末尾知识点卡片
⑤ 沉淀回流     错题→错题本 · 未掌握→mastery · 归因→画像 · 记录→知识页归档
```

**输入形态**：一期**文字题面**；二期「拍照搜题」考虑**多模态大模型**（比传统 OCR 更对口公式/几何/手写），需配"题面识别可编辑"兜底。🟡

**三态解题模式**（触发：**记忆上次 + 侧栏可切换**）：

| 模式 | 说明 |
|---|---|
| **直给** | 完整解答一次给出（适合有储备、想快看者）|
| **解析式** | 对解题步骤逐项说明/解析；简单题/无法列步骤的退化为思路说明；按序输出卡片式解析 |
| **引导式** | 多轮交互教学循环（见下）|

- **解析式 / 引导式**：适合折叠的部分可**折叠收起**。
- **三态统一**：无论哪种模式，**最后都输出知识点卡片**。

**多解法（理科）** ✅

- 解析式 / 引导式在**开头点出**本题可能存在的其他合理解法（**只列名目，不展开**）；
- **默认以最合理 / 最贴合的解法**完成主输出；
- 用户要求展开其他解法时，解题**侧面板横向分出一页**，面板上部出现 `1/2`（或更多）指示器，第二页开启新的解答过程讲解；
- **解法上限 2–3**，且**默认只生成主解**，用户点开才生成其余页（省 token）。

**解法范围约束** ✅：输出**限制为中学阶段解法**（prompt 约束）——禁止超纲方法（如用洛必达法则解高中题、用微积分解初中题）。

**语文 / 外语阅读题：原文回溯** ✅

- 对于"答案需回溯原文"的题型（概括、指代、对应句），解答中**简略标出对应原文内容**并支持**跳转查看**。
- 实现：题面原文**分块编号** → 模型输出引用块 ID → 前端高亮 + 跳转。
- 原文**会话内保留、不落库**（与 §4.8.2 的文件处理一致）。

**引导式交互循环：**

```
模型先问「你想到哪一步了？」
├─ 有思路 → 用户口述思路 → 模型提示 / 指正 / 分析
└─ 无思路 → 模型先出「知识点卡片」→ 从题干开始细析
             → 每段输出「步骤卡片」→ 每步后抛一个引导问题
                  └─ 用户可中途打断「已有思路」
                       ├─ 退出引导教学
                       └─ 或发送接下来的思路 → 模型判断 → 续接 / 纠正下一步
```

引导式是**回合制对话循环**（流式可中断 + 进度可保存 + 提问-等待-判断状态机），落在「单对话 + 上下文栈」内，无需另起炉灶。

**知识点查询**：复用现有 **embedding 能力**（FAISS + `embedding_service` / `vector_store` / `kb_vectors`），把题面 embedding 后检索相关知识点。
⚠️ **机制现成、内容待重构**：embedding 是检索手段（管线已就位、默认 `off` 降级 name_fuzzy），检索质量取决于知识点库内容（后续重构）。

**正确性降险**：分步结构化 + "AI 解题可能有误，请核对"明示；**不过度依赖检索增强**，知识点库重构后再接。

**知识点讲解（/讲知识点）** ✅

区别于搜题（解一道题）：讲解是"讲透一个概念/知识点"，由学习过程中对某知识点的卡点触发（预习/复习流程内）。

实现分层（成本从低到高）：

| 层 | 内容 | 成本 | 规模化 |
|---|---|---|---|
| L1 结构化文字讲解 | 分节：定义 → 来龙去脉 → 公式 → 易错点 → 例题 → 自测 | 低 | ✅ |
| L2 结构化 + 轻交互 | 折叠思考、选择自测(对错反馈)、表格着色、公式排版 | 中 | ✅ 通用组件 + schema |
| L3 富交互仿真 | Canvas 分子/运动模拟、滑块调参、动态判定变色 | 极高 | ⚠️ 仅"参数化模拟器" |

- **L3 是精品方向 🟡**：只做精选核心知识点，用**参数化模拟器模板**（化学平衡、匀变速运动、函数图像等"可仿真"类），不逐点定制。
- **成本是"双成本"**：技术（仿真/可视化）+ **内容（教学设计）**；"讲透"的灵魂是教学设计，LLM 能搭框架但难稳定复现洞察。
- **分阶段**：先 L1 + 部分 L2 跑通意图，L3 作长期精品化投入。

**讲解内容的留存策略** ✅

- **回顾 = 取原文**（保证一致性）；**重新讲 = 现生成**（可按当前掌握度调深度）。**两者并存**，不要用一个顶掉另一个。
- ❌ 不采用"只存要点、回看时重生成"：存储比推理便宜几个数量级，且**重生成恰恰保证不了一致性**（模型有随机性）——而讲解的价值恰恰在于"上次那个讲法、那个例子"。
- **pilot 阶段做 3–5 个精品讲解样例**，用于验证 schema 与生成管线。
- ⚠️ **精品内容是预制入库、长期保存**，与动态生成的严格区分。

「查」分支：查概念/公式/定义，轻量一次性，返回结构化卡片，复用知识求助呈现，成本最低。

**外语单词 / 短语的浮窗回复** ✅：在随手问浮窗（§3.9）里查词时，回复**按查词卡片模板结构化输出**（音标 / 词性 / 释义 / 例句 / 搭配），不用自由文本——零成本（prompt + 结构化输出），但体验接近专业查词工具。

### 3.6 计时（专注态）✅
- 仍是**独立页**，但逻辑变化：
  - **全屏沉浸**，**不出现导航**；
  - 仅保留基础计时功能（暂停/结束等）；
  - 可**呼出 Chat 侧栏**，但此时 Chat 被**锁定为「知识求助」类**（搜题/讲知识点/查；闲聊/建任务不可用）——"专注中只允许为眼前题服务"。（属「**受限 Chat**」机制的第一种配置，另一种见 §3.9.1 随手问浮窗）
- 结束流程：转入**学习记录收尾**（见 3.7）。
- 计时中的知识求助：**临时会话**，但有记录与**归档** ✅（归档去向见知识页）。

**退出 / 返回与中断恢复** ✅：
- **只留"结束"一个出口，不做"挂起"**——专注态仅「暂停 / 结束」，退出专注 = 结束 → 收尾（避免"僵尸计时"）。
- **服务端持久化"进行中的计时会话"**（`started_at` + 模式 + 目标时长 + planId），前端仅是视图；回来按**真实经过时间**恢复，根治"路由 state 丢失"技术债。

**计时双模式** ✅：

```
计时会话 = {
  mode: "countdown" | "countup",   // 倒计时 / 正计时
  started_at,                      // 两种模式都有
  target_minutes,                  // 仅 countdown；countup 为 null
  plan/task/subject 引用
}
恢复（按 mode 分支）：
  countdown → 剩余 = target − 已过；≤0 视为已到点
  countup   → 累计 = now − started_at（无到点，随时结束）
```

- **倒计时（countdown）**：有目标时长的任务；**正计时（countup）**：无需严格限制时间的计划。
- 触发默认：任务带时长 → 倒计时；不限时（如"复习昨天学的"）→ 正计时；计时页可切。
- 正计时结束走**同一套收尾**，仅无"到点"，累计时长正确即可。

**倒计时到点 = 软提醒** ✅（不强制结束）：
- 到点（remaining=0）→ 触发提醒，**不自动结束**；
- 用户可**结束**（走收尾，时长 = target）或**继续**；
- 继续则**平滑转入正计时语义**（持续累积），结束后时长 = target + 续学时长；
- 到点后若放任不管，续学部分走**正计时的僵尸治理**（超上限 → 裁决卡）。
- 提醒方式（声音/震动/通知）为实现细节，此处不展开。

**僵尸计时治理** ✅：

僵尸 = 一个"进行中"的计时会话长期无正常收尾（直接关 App / 遗忘 / 断连）。目标不是"消灭"，而是**不污染数据、不制造困惑**。

1. **超时失效**：给"进行中"状态一个生命周期。
   - 倒计时：到点后仍未结束 → 进"待收尾"，**时长封顶 target**；
   - 正计时：累计超过上限（如 >6h 或长时间无操作）→ 判"异常"，截断。
2. **恢复裁决卡**：回来发现异常会话时弹卡，**不自动记账**——
   「上次计时似乎没正常结束（已计 X 分钟）· [保留按 X 记] [丢弃] [手动改时长]」。
3. **有效时长 ≠ 墙上时长**：学习记录 `duration` 只记可信有效时长——倒计时 = `min(经过, target)`；正计时 = 经过时间但异常时必须用户核实。

- **正计时是僵尸重灾区**（无到点兜底），裁决卡对其尤其必需。

### 3.7 学习记录：自评双轨 + 事后可回写 ✅

**核心立场：学习记录是「可事后回写的活实体」，不是「提交即封存」的快照。**

#### (a) 计时收尾：三层形态 + 数值来源 ✅

**核心改造：从「拦截式量表」变「非拦截式轻卡」——结束动作本身不拦。**

1. **结束瞬间（0 步，可立即走）**：展示"本次已记录 · 科目 · X 分钟" + 轻按钮 [完成 ✓] / [收起]。
2. **轻收尾卡（可选，约 10 秒）**：
   - 完成度（唯一"半强制"问句）：完成了 / 做了一部分 / 没完成；
   - 一句感受（叙事轨 · 可选）：模型提情绪/疲劳/难度/归因；
   - 情绪快捷词（可选兜底）：积极 / 一般 / 消极（非 1–5 刻度）。
3. **延后引导（不出现）**：正确率/错题"之后随时可补"。

**数值来源策略（B 方案）**：
- **直填（可靠，进算分）**：时长（自动）、完成度、情绪（三词直填）。
- **口语转译（软，进算分）**：专注 / 疲劳 / 难度由模型从"一句感受"转译。
- **转译不出则缺省**：状态引擎容忍缺失；游客无 AI → 走极简结构化表单。

**口语转译兜底** ✅（软字段宁缺毋滥，静默降级不打扰）：

| 转译失败情况 | 处理 |
|---|---|
| 用户没说话（无输入）| 三字段＝null，缺省 |
| 语义模糊提不出（"还行吧"）| 留空，不硬猜 |
| 只提出部分 | 能提的提、不能的留空 |
| 低置信度 | 只采高置信字段 |
| 技术失败（AI 不可用/超时）| 静默 null |

- **状态引擎对缺失**：核心自评**在**（完成度＋情绪，直填）→ 正常算分，软字段缺则**跳过**、按可用部分归一化；核心自评**也缺** → 不硬凑，标签降级 `insufficient_data`（复用引擎已有态）。
- 一句总结：**软字段缺失只"变粗"，不"变假"**。

#### (b) 正确率与错题：三态可填，系统容忍缺失 ✅
- **三态**：**结束即填**（当场已对答案/知道结果 → 收尾卡给低摩擦入口）；**延后补**（老师讲完才知道 → Chat 锚定回溯）；**永不填**（懒得回填 → 系统接受）。
- 三态中都**不强制**：正确率/错题是可选、可跳、可延的项。
- **数据层 nullable**：正确率/归因字段允许缺失；状态引擎、mastery（已有 MIN_SAMPLES 置信度规则）、画像归因提取都**容忍缺失**——不报错、不假造、不因缺失扭曲结果。
- 正确率与错题在收尾卡上**拆开**：正确率偏"可当场填"（比例/对了几题）；错题偏"延后整理"（归档知识页/错题本）。

#### (c) 反馈锚定回溯
- Chat 里对历史实体的反馈，需能**锚定**回具体对象。模糊指代（"上次那份数学卷""之前那条计划"）由模型消解：
  1. 识别为「对历史记录的事后补充」；
  2. 拉出近期计划/记录候选；
  3. 弹**锚定确认卡**（"是周三 20:00 数学计划那条吗？"[✓ / 换一个]）；
  4. 确认后**回写 + 联动**（正确率补记 · 错误点→错题本 · 归因→画像）。
- 实体链：**计划(Plan) → 任务(Task) → 学习记录(Record)**，反馈可挂任一级，用户心理锚定在"计划"级。
- 「锚定确认卡」是**可泛化的通用交互**（补记录 / 补错题 / 报目标进度都复用）。

### 3.8 对话记忆形态：**不做对话历史**（差异化）✅

**核心立场**：Chat **不提供对话历史列表、不提供「新建对话」**。全产品只有一条持续演进的对话。

这是**刻意的产品选择，不是功能缺失**——它把"记忆"从一种形态换成了另一种：

| | 通用 AI | EpochX |
|---|---|---|
| 记忆形态 | 线性对话流水 | **结构化沉淀**（画像 / mastery / 学习记录 / 归档）|
| 用户能否回看 | 能，翻原文 | 不能翻对话原文 |
| 用户能否修改 | 不能 | **能**（画像可看 / 可改 / 可删，§4.3）|
| 记忆是否随对话消失 | 是（开新对话 = 失忆）| 否 |

- 一句话对外表达：**「你看不到往日的对话，但模型记得关于你的一切」**——而且这份记忆**可检查、可修改**。
- 三条支撑论据：
  1. **学习助手 ≠ 通用 AI**：用户要的不是"上次我说了什么"，而是"我现在该学什么"。
  2. **合规顺带优势**：未成年产品的聊天文本不长期留存，与 §4.6「具体事件不进画像、只进情绪状态」是同一条思路。
  3. **与 D2 天然自洽**：单会话模型本就没有历史列表——此前只是没人说破。

#### 3.8.1 会话边界：连续使用周期 + 不活跃老化 ✅

D36 说栈是"会话级"、§3.4 说"随会话结束失效"，但**只有一条对话时"会话"永不结束**。故明确定义：

- **会话 = 一个连续使用周期**，跨刷新 / 跨设备持久（服务端持久化，前端仅是视图）。
- **老化规则**：无交互超过阈值 → 栈内上下文老化清空。阈值实现时定（建议 24h–7d 区间，默认偏长）。
- 沉降物**不随会话老化**，各走各的 TTL。
- ⚠️ **不采用「每日零点重置」**——23:59 聊到一半就被清空不可接受。

#### 3.8.2 翻篇：无「新建对话」，靠意图切换 ✅

- **默认**：不设 New Chat 按钮。翻篇由**意图切换**无声完成——斜杠命令 / 按钮 / 模型裸判一换，上下文栈 LIFO 自动让位。
- **兜底**：提供弱化的「**清空当前上下文**」动作，藏在「+」菜单或设置里。
- ⚠️ 命名**必须避开「新建对话」**——它暗示存在对话列表，与本节立场冲突。
- 计时中的知识求助本就是临时会话（§3.6），不在此列。

#### 3.8.3 原文留存：短期留存 + 产品不可见 ✅

"用户看不到历史" ≠ "服务端不存"。分三层：

| 层 | 存什么 | 存多久 | 用途 |
|---|---|---|---|
| **结构化沉淀**（真记忆）| 画像条目 / mastery / 学习记录 / 归档 | 长期 | 模型"记得你"的来源 |
| **行为埋点**（§8）| 意图 / 卡片事件 / 锚定结果等**结构化事件** | 长期 | 产品迭代 |
| **对话原文** | 消息文本 | **短期**（窗口实现时定，建议 7–30 天）| 安全审计 + 异常排查 + 上下文接续 |

- **原文短期留存不可省**：§4.6 的 L3 危机响应需要事后可追溯——完全不存会导致"出了事查不到用户说了什么"，对未成年产品是**反向风险**。
- **产品上不给任何回看入口**：无历史列表、无搜索、无导出。
- 原文**不入画像**、到期删除。
- ⚠️ **与 §8 的口径划分**：埋点存的是结构化事件，对话原文是独立的安全留存，两者用途与留存期不同，**不可混为一谈**。

#### 3.8.4 连带项 ✅

- **画像升格为信任基础设施**：不提供对话历史，**以「画像可看 / 可改 / 可删」为前置条件**（§4.3）——否则等于把用户关进黑箱，他无从知道"你记得我什么"。
- **讲解也要归档**：§4.4 知识页原只有「搜题归档」；没有对话历史后，用户很可能重复问同一个知识点。扩为「**搜题 + 讲解 归档**」。

#### 3.8.5 跨登录的临时细化记忆 ✅

不做对话历史，不代表**每次都从零开始**。

- **机制**：会话结束时生成一份**话题摘要**（结构化 2–3 条，"上次聊到 X""卡在 Y"），**不存对话原文**；
- **用途**：下次冷启动时注入，让模型**接得上两句**（客套一下、提一句上次的事）；
- **落点**：它正是 §1.3 空态问候语「**预设骨架 + 动态填充**」中**动态内容的唯一数据源**——两者是同一件事的两端；
- **成本**：极低（一次性生成 + 长期存结构化条目，不是存流水）。

> 一句话对外表达（与 §3.8 主体合并）：**「你看不到往日的对话，但模型记得关于你的一切，也记得你上回聊到哪。」**

### 3.9 划选与随手问浮窗 ✅

划选（文本 / 图片区域）后其实是**两种意图**，分两条路径：

| | **引用到主对话**（主路径）| **随手问浮窗**（旁路）|
|---|---|---|
| 场景 | 想就这个点展开聊下去 | 就一个词 / 小概念顺手问一下，不想打搅主线 |
| 上下文 | 双向共享，后续进主对话 | **单向继承**——浮窗的对话不回流主对话 |
| 产物 | 进主对话流 | 不进主对话，**只有收藏** |
| 触发 | 划选工具条 `[在主对话追问]` | 划选工具条 `[随手问]` |

#### 3.9.1 随手问浮窗 = 「受限 Chat」

它**不是第二种会话**（D2 明确排除多线程），而是**栈外临时旁路**——不入上下文栈、不沉降、关闭即销毁。

**通用机制：受限 Chat** —— 同一机制已有先例（§3.6 计时页侧栏），两种配置：

| | 计时页侧栏（已有）| 随手问浮窗（新增）|
|---|---|---|
| 锁定意图 | 知识求助（搜题 / 讲知识点 / 查）| **基础问答**——不进搜题 / guide / goal 等模式状态，不产出卡片 |
| 上下文 | 临时会话 | 继承主对话、**不回流** |
| 产出沉淀 | 归档到知识页 | **仅收藏** |
| 生命周期 | 计时结束即归档 | 关闭即销毁 |

#### 3.9.2 浮窗规则 ✅

- **继承什么**：主对话的话题背景 + 相关卡片/引用（够理解上下文即可），**不继承隐式上下文**。
- **多轮可以**：浮窗内部可继续追问（"这个词什么意思" → "那它和 X 有什么区别"）；**不递归**——不能从主对话再划选发起新浮窗。
- **同时只能展开一个**（多个即变并行会话，与 D2 冲突）；**挂起可多个**。
- **不影响主对话状态机**：主对话若正在跑引导式搜题（§3.5 的提问-等待-判断循环），浮窗问完回来时**必须还停在原步骤**。
- **拖动**：支持。
- **结束会话**：浮窗底部「结束会话」→ 禁止输入但**不关闭**；按钮变为「添加到主对话」。
- **挂起**：右上角挂起图标 → 收起，保留浮窗开头的部分语句作为预览；收起态有「展开」和「×」。挂起**会话内保留、老化后清除**。
- **添加到主对话**：**只带显式输入输出、不带隐式上下文**，附加类似"这是用户临时的对话"的提示，以「浮窗对话 ✕」的引用块形式置入输入框首部，用户可续写后一起发送。
- **收藏等同**：享有与主对话同等的划选收藏能力（收藏是全局能力，不受上下文限制）。
- **计费**：照常计 credits，跟随主对话的推理等级，浮窗内不单独给档位。

## 4. 功能从属关系

### 4.1 数据 / 复盘 / 建议 的重新归位 ✅

| 原功能 | 新归位 |
|---|---|
| 个人数据总览 | → **个人中心** |
| 复盘 | → **chat 侧面板**（作为可生成内容）＋个人中心「复盘记录」（可一键复盘）|
| 建议 | → **首页「推荐」组卡片**（状态 / 内容 / 目标规划 三类合并，卡内用 type 标签/颜色区分；见 §3.1 推荐卡片）|

### 4.2 目标树 ✅
- 形态：**长期目标下挂多个短期子目标（父子树）**，模型可拆解/规划。
- 展示：chat 侧面板 = **简略版（父子缩进列表）**；个人中心 = **详情版（树 + 时间线叠加）**。
  - 树表达**从属**，时间线表达**执行节奏**，两者正交可叠——短期目标既是树的子节点、又是时间轴的点。

### 4.3 用户画像 ✅

> ⚠️ **已摘掉合规暂缓**：§3.8.4 已把「画像可看 / 可改 / 可删」定为**不做对话历史的前置条件**，前置条件不能是暂缓项。它现在是**信任基础设施**，不是锦上添花。

- 从「成绩」扩展为「成绩 + 兴趣 / 性格 / 经历 / 归因习惯」等。
- 维护方式：**模型隐式提取写入**；用户**可修改 / 可删**，但**不可手动新建条目**。
- 输入源：闲聊内容 + **自评叙事轨 / 事后反馈描述**（"卡在 X 类题""精力没分配好"等归因性表述是画像一等原料）。
- **边界**：闲聊内容提取**学习域**信号（学科倾向/学习习惯/学习归因）+ 生活域**情绪状态**（情绪基调）；但**具体事件/细节**（家庭/人际冲突、当事人）**不进画像**（见 §4.6）。
- 画像里存的是**提取后的结构化条目**（如「薄弱知识点=函数/单调性」「习惯=时间分配不均」），而非原始流水；条目可看/改/删。

#### 4.3.1 四个分组（按消费方划分）✅

| 组 | 内容 | 主要消费者 |
|---|---|---|
| **学习画像** | 学段/学科倾向/薄弱域/优势域/**学习习惯**（时间分配、复盘频率、**解题习惯毛病**如"计算易错""常落单位"）| 建任务、内容建议、mastery 校准 |
| **状态画像** | 易疲劳时段、情绪基线、专注特征 | 状态建议、节奏规划 |
| **归因画像** | 用户自己的归因习惯（"我总是粗心"）| **建议语气**（决定怎么说话，不决定说什么）|
| **兴趣与经历** | 兴趣、性格、经历 | 仅闲聊语气 |

- **非知识类"毛病"要记**：计算差、落单位这类**解题习惯问题**属于学习画像，模型应记忆并影响后续输出（解题时主动提示检查计算 / 单位）。
- **库外知识不进 mastery**：知识点不在系统知识点库内时，**只进画像归因**（"卡在函数单调性"这类表述），**绝不硬塞进 mastery**——硬塞会让掌握度变成没有对比基准的数字。

#### 4.3.2 注入上下文：按意图选组，不全量 ✅

| 场景 | 注入 |
|---|---|
| 建任务 / 计划 | 学习画像（+ 状态画像）|
| 闲聊 | 兴趣与经历 + 情绪基调 |
| 建议 / 复盘 | 归因画像 + 状态画像 |
| 解题 / 讲解 | 学习画像（含解题习惯毛病）|

**不全量注入**——全量会爆 context 且引入噪声。

#### 4.3.3 语言风格是画像字段，不是纯设置项 ✅

- **激活页**（§1.2）提供若干预设风格供选择；设置页可改。
- 用户在对话中提出风格要求（"你说话别这么啰嗦"）→ **自动生效**，且**设置里的选项显示为「自定义」**（不显示详细内容）。
- **对话中的显式要求优先于设置项**（与"以最新口头结论为准"一致）。
- ⚠️ 自动调整后**必须告知用户**（"已按你的要求调整说话风格"），否则用户不知道发生了什么。

#### 4.3.4 画像驱动计划（举例）✅

制定计划 / 目标时，模型应读画像并调整策略。例：**用户有拖延倾向** → 策略是**缩短单次时长 + 增加检查点**，而不是砍总量（砍总量会让用户更不想开始）。

### 4.4 知识页 ✅

定位：**「学科掌握地图 + 知识资产仓」**，回答"我对各学科知识掌握得怎么样"。与个人中心分工：个人中心管**学习行为**，知识页管**知识掌握**。

**内容构成：**

| 模块 | 说明 |
|---|---|
| 学科掌握度总览 | 各学科/知识域掌握度分布，**薄弱域显式标签**（如"几何：薄弱"）；是「画像识别薄弱域 → L3 参照」的入口 |
| 知识点检索 | 全科全学段知识点检索（对点预习/复习）；**质量前提**是知识点库 |
| 知识点详情页 | 单点：定义/易错点/关联题/掌握度/难度/关联知识点；是**难度双层模型**的载体 |
| **题本**（错题本升格，见 §4.4.1）| 题本 CRUD + 艾宾浩斯复习 + AI 归因；含"错因统计"视图；支持**按教学课时顺序排列**（§4.9）|
| 搜题 + 讲解归档 | 计时/对话中搜题与知识点讲解的记录归档（无对话历史后的重复提问兜底，见 §3.8.4）|
| 知识图谱 | 知识点关系可视化（掌握度色阶）|
| 难度双层模型 | 官方基线 + 个人覆写(免审核) + 众包信号 |

**难度双层模型** ✅：
- **官方难度基线**：全局、审核维护（慢）；
- **个人覆写**：用户对难度分级上报修改，**本账号内免审核即时生效**（仅改个人视图）；
- **众包信号**：个人调整匿名聚合后反哺官方难度校准；
- 个人覆写与官方的**落差**是画像信号（落差大 → 偏科/已掌握，喂 mastery）。
- ⚠️ 难度覆写若用于聚合，属"学生水平"敏感数据，**匿名 + 最小群体**。

#### 4.4.1 错题本升格为「题本」✅

**根本问题：错题本是"复习队列"还是"错误记录"？** 现按后者实现，但用户还想存"好题 / 想再复习的题"——那是前者的需求。升格后两者都能装。

**两个正交维度**（决定一个题"是什么"与"为什么在这儿"）：

| 维度 | 取值 | 说明 |
|---|---|---|
| **错因** | 概念不清 / 计算失误 / 审题错误 / 知识盲区 … | 错题专有 |
| **意图** | 想复习 / 好题 / 典型 / 存疑 | 用户主观 |

于是：
- **错题** = 有错因标记；
- **star 题** = 只有意图标记、无错因；
- **复习队列**（艾宾浩斯）= 两者都进；
- ⚠️ **mastery 与归因只消费「有错因」的**——新增 star 完全不污染现有逻辑。这比另建一个"好题本"干净得多。

**添加规则：明示 → 直加；推断 → 必须确认** ✅

| 来源 | 处理 |
|---|---|
| 用户亲口说"这是错题" | **明示**，低摩擦直加 |
| 多模态「检查」场景，模型判定为错题 | **推断**，必须过用户确认（手写识别本身就会错）|

- **入口时机与位置**：统一挂在**结果卡片的操作区**——① 搜题 / 讲解末尾的知识点卡片旁 ② 检查完成后结果卡上 ③ 题本页内手动录入。

**返考与相似题** ✅

- **淡化"组卷"措辞**，改称「**复习**」/「**小测**」——完全做成组卷会让用户抵触。
- **相似题生成**放在**题本内**（选中某题 → 生成相似题）与**知识页**（按知识点生成）。理由：生成相似题需要知道"考哪个知识点"，这两处都有该上下文；Chat 里也可通过 `/出题` 触发，但不是主入口。

**其它**：
- 个人知识笔记/标注：🟡 二期（范围易蔓延）。
- **学习路径/知识进阶：归首页「内容建议」，不放知识页** ✅。

### 4.5 社区（板块三）✅ 定位升级 + L1–L4 全要

- **保留**，展示页收进**个人中心**。
- 价值定位：**不再是「看大致排名」，而是「横向坐标 + 群体智慧引擎」**。
- **L1–L4 全要**；**L4 严肃开发，是产品点**；L5 社交/连接个体：🔴 未成年红线，不做。

卡片形态（个人中心内，3 张卡）：

| 卡 | 对应 | 内容 |
|---|---|---|
| **「你在哪」** | L1 | 4 指标可切，分位 + 直方图，高亮自己落点 |
| **「你的趋势 vs 同龄人」** | L2 | 个人状态走势折线，叠加群体 P25–P75 阴影带 |
| **「和相似的人」** | L3 | 匿名聚合"相似人群"典型画像：节奏/常见卡点/状态分布 |

- **L4 不做独立卡**，而是**融进首页建议**：L4 的触达方式即 §3.1 推荐卡「**洞察**」组。✅

**L4 可解释性标注** ✅：

原则：**轻、真实、不吓人**——不是堆原始统计（不摆 p25/50/75），而是让用户知道"这条洞察有依据、来源对、够新鲜"。

每条洞察卡底部一行小字，三要素：

```
基于 N 名匿名同龄人 · 同年级·相似节奏 · 近 4 周
```

- **N = 真实聚合数**，天然 ≥ k=20（呼应社区"不足 k 不返回"——N 不够时该洞察不生成）；
- cohort 范围（来源对的那群人）+ 时间窗（数据新鲜）；
- 可点开「来源说明」看 cohort 定义与口径，**默认收起**，不打扰。
- 触达即洞察组卡片自带标注，不额外做入口。

#### L3 相似分段的落地设计 ✅

**核心原则：分组按「维度」，不按「人」。** 一个人不被塞进单一整体组，而是在每个维度上独立找同路人（例：几何弱 + 电学强 = 同时属于两个不同参照组）。

**参照维度二分：**

- **掌握维度**（学得怎么样）：按**学科/知识域**独立找参照，粒度挂「知识域/学科」层（知识点太细、样本不够不可作组）。呼应项目一级原则「按学科分、不做跨学科合并」——画像负责"识别我哪个域弱（知识点→域）"，L3 负责"在这个域上找参照"。
- **行为维度**（怎么学）：6 个维度，**每个独立分组、不交叉**。

行为维度清单（每个独立成参照维度）：

| 维度 | 粗档切分 | 数据来源 |
|---|---|---|
| 投入时长（周均） | 轻 / 中 / 重 | 学习记录 `duration` |
| 投入规律性 | 稳定 / 波动 | 每日时长变异系数 |
| 复盘频率 | 高频 / 低频 / 从不 | 复盘行为日志 |
| 目标类型 | 短期 / 长期 / 双轨 | `Goal.type`（离散枚举）|
| 学习时段 | 晨 / 午 / 晚 / 深夜 | 学习记录 `started_at` |
| 疲劳-恢复模式 | 高负荷 / 均衡 | 自评 `fatigue`/`focus` 趋势 |

**分组原则：**
- **多维独立、不交叉**——绝不把多维度笛卡尔积切组（3 维×3 档=27 组、5 维=243 组，组会崩空、凑不满 k=20）。
- **分组刀 vs 描述标签**分离——刀少而粗（默认主刀 = **投入时长**），其余维度作为"同路人画像"的**描述标签**，不参与切分。
- **默认主刀 + 可切换**——社区参照区默认展示投入时长，用户可切换看其他维度。行为会漂移 → 归属带**时间窗（近 4 周）**、动态刷新。

**数据口径：**
- **自己的数 = 精确值**（来自自己行为日志，如"本周 8.3h"）；**群体定位 = 分位数区间**（P25/P50/P75，如"落在中上投入 [7h,11h]"）。
- 分位数而非拍脑袋绝对值：自适应、匿名友好、与项目已有 p25/p50/p75 一致。
- **连续型**维度（时长/规律性/时段/疲劳）用分位数分档；**离散型**（目标类型）直接枚举。
- **可解释性**：分位规则讲成人话（"你是全体里投入量靠前 1/4 的人"），不堆数字。

- **L3 参照产出（三个特色，递进）：**
- A「同路人画像」：静态参照（打底）。
- B「偏离预警 / 前瞻轨迹」：动态价值，差异化核心。
- C「共性卡点 / 难度共识」：反哺建议与知识页难度众包，让 L3 成为引擎一部分。

**B 偏离预警 + 前瞻轨迹** ✅：

区别于 L2（对全体同龄人），B 对**相似 cohort**，更有针对性。

- **偏离预警**：
  - 口径：用户某指标值落到 cohort 分布最外沿 = 显著偏离（如「超 P75 + 1.5×IQR」或「最外 5%」）。
  - **偏离 ≠ 报警**：必须带语义解释，区分正向（你更勤奋）与负向（你有风险），不机器式弹红点。
  - 触达：**首页「洞察」组卡片为主**（被动，不推通知）；**个人页二级菜单角标为辅**，**不上首页/首屏入口**。
- **前瞻轨迹**（分层）：
  - **一期·粗粒度**：看 cohort 状态**变化方向**（本周 vs 上周斜率）做趋势顺延——"同类人疲劳显著上升，未来一周你大概率也会，提前减量"。无需时间对齐。
  - **二期·精细**：按"进入阶段第 N 天/周"对齐，给"第 3 周典型状态"式精确预测（深水区 🟡）。

**C 共性卡点 + 难度共识** ✅：

- **共性卡点**：cohort 内高频归因标签匿名聚合（"几何薄弱""周三疲劳"），喂画像 + 建议。
- **难度共识**：cohort 对知识点的难度共识 → 喂知识页「难度双层模型」的**众包信号**（坐实之前那句空话）。
- **与知识页联动口径**：难度详情**三方并列**（官方基线 / 个人覆写 / 相似人群共识），且**仅在出现显著落差时提示**——「你觉得简单、人群普遍觉得难」→ 画像信号（已掌握/偏科）。

### 4.6 情绪安全与危机响应 ✅

**定位**：处理"闲聊中倾诉生活负面情绪"的横切场景（学校/家庭烂事、强烈负面情绪）——跨闲聊、不属于任何业务模块。

**三档定性**：

| 档 | 表现 | 产品姿态 |
|---|---|---|
| L1 日常负面 | 考砸了、拌嘴、"好烦" | 共情 + 轻引导，正常对话 |
| L2 强烈负面 + 潜在风险 | 持续低落、"没意思"、关系破裂 | 认真倾听 + 温和关注 + 提议求助 |
| L3 明确危机 | 自伤 / 自杀 / 伤害他人表述 | 危机响应，转介 |

**核心边界：学习助手 ≠ 心理医生**——姿态是「识别 → 倾听（不评判）→ 转介」，不说教、不越界做心理咨询/诊断。

- **画像边界（P1）**：负面倾诉的**情绪状态进画像**（如"持续低落""考试焦虑偏高"）；但**具体事件/细节**（当事人、冲突细节、家庭人际事件）**不进画像**。学习域照常进画像。
- **危机响应（P3）**：接既有 `safety_filter.py` + `CRISIS_RESPONSE`；覆盖 **L2→L3 升级识别**（不等到明说自残才反应）。L3 必须转介：求助渠道 + 建议联系可信成年人 / 监护人 / 学校心理老师。
- **回应基调约束（P2）**：留到各情景 prompt 约束编辑时一并写（此处不单列）。
- ⚠️ 本项属**安全底线**，不随"合规暂缓"跳过。

### 4.7 设置与授权归位 ✅

**背景**：新 IA 里有几处此前没有落点——监护人授权（合规设计底线）在新架构中**完全缺席**、设置页被压缩成 IA 树括号里的一个词、游客的登录出口未写、站外通知未定。本节一次性收口（D41–D44）。

#### 4.7.1 监护人授权：入口两处、页面一处 ✅

- **页面归位**：个人中心 → 设置 → **「授权与隐私」子页**（不是独立页，也不与设置同级）。
- **授权状态卡**：已授权 / 待确认 / 未授权，卡内可发起、可撤销。
- **强制门槛**：建档流程中判定 **<14 岁 → 必须完成监护人授权才能继续**——这不是"想起来才去开"的可选项。
- **入口两处、页面一处**：① 建档流程强制触发；② 设置 → 授权与隐私 常驻。两端都指向同一个页面。
- **补上一个既有的缺口**：设置页「匿名群体参照」的文案已经写着"参与需经监护人授权"，但流程此前**没接**——话说了、事没做。开启该开关前需校验授权状态，未授权则引导至本页。
- ⚠️ 属**设计底线**（pilot 阶段必须做），与 §4.6 情绪安全同级，不随"合规暂缓"跳过。
- 后端既有资产可直接复用：`/guardian-auth` 页、202 返回 token 的确认闭环、14 岁以下独立规则。

#### 4.7.2 设置页瘦身：只留「账号与资料」+「授权与隐私」 ✅

| 现有内容 | 新归位 |
|---|---|
| AI 三开关（自动调权 / 发送文字给 AI / 知识复盘出域）| → 授权与隐私 |
| 匿名群体参照开关 | → 授权与隐私 |
| 监护人授权 | → 授权与隐私 |
| 引擎权重调参（α / β / w1–w6）| ❌ **移出用户产品** |

- **权重面板移出的理由**：它把规则引擎的内部参数直接摆给用户，与新形态「引擎算事实、AI 负责表达」的立场相悖；对目标用户（中学生）也没有可读性。
- **去处**：隐藏，或降为内部调试入口——不出现在任何用户可见导航里。
- 🟡 **二期候选**：把权重调参**改造**为自然语言个性化（"我更在意专注度而不是时长" → 映射回权重），与「Chat 为核」形态契合。**本次不做。**

#### 4.7.3 通知：站内被动、站外仅事务性 ✅

| 层 | 做什么 |
|---|---|
| **站内** | 被动触达为主：首页推荐卡（Go on / 洞察）+ 个人中心二级菜单角标 |
| **本地** | 计时到点软提醒（声音 / 震动），属实现细节 |
| **站外** | **仅事务性邮件**：验证码 / 找回密码 / 监护人授权。**不做**学习提醒类推送 |

- 与 §4.5 L3-B 口径一致：偏离预警"不上通知、不上首屏入口"。学习类推送会与该口径直接打架——除非主动改那条，否则默认不做。
- SMTP 双模（real / mock）已就位，事务性邮件是**既有能力复用**，非新增工作量。

### 4.8 收藏与知识资产 ✅

#### 4.8.1 收藏：非课内知识与任意输出的留存 ✅

用户问"黑洞怎么形成的"这类**非课内知识**，模型回答了，用户想存下来——这是真实需求。

- **不塞进知识点库**：知识点实体挂着 mastery / 难度 / 图谱关系，混进去会污染。
- **也不另建"个人知识库"**：那是 Notion，范围会崩。
- 解法：**「收藏」**——任何模型输出（闲聊 / 讲解 / 搜题 / 非课内问答 / 图片圈选区域）都可一键收藏。
- **边界一句话**：**知识页 = 课内、有结构、可评测；收藏 = 一切、无结构、不可评测。**
- 与 §3.8「不做对话历史」**不冲突，反而是互补**：系统不被动留存一切，但**你想留的可以留**。

#### 4.8.2 收藏必须存快照（关键约束）✅

⚠️ §3.8 决定不存对话历史（原文只做短期安全留存），因此**收藏必须存快照，不能只存引用**——否则原文到期一删，收藏就变成一堆死链。

- **图片圈选的收藏必须存裁剪后的小图**（原图不留存，只存坐标同样会变死图）。

#### 4.8.3 归位与分组 ✅

| 内容 | 归位 |
|---|---|
| 题本 / 知识点记录 | → **知识页**（可复习、可评测）|
| chat 收藏 | → **个人中心**（不可评测）|

- 与 §4.8.1 的边界完全一致：**可评测的归知识页，不可评测的归个人中心**。
- **自定义分组 + 内置分组正交**：内置分组（学科 / 时间 / 掌握度）是**筛选维度**；自定义分组是用户标签字段。⚠️ 别让用户给同一个东西打两套分组，会打架。
- chat 收藏只需自定义分组 + 时间排序。
- **展现形式**：卡片 + 来源引用，**不做文本直列**。

#### 4.8.4 收藏的交互 ✅

- **内容不可编辑**（保证留存的真实性），但支持两种标记：
  - **划选高亮**；
  - **「虚化」** ⭐——把选中文本做模糊显示处理。单条收藏全屏展开时，**方向键**切换焦点至各处虚化，**空格**临时解除虚化。
    - 用途一：隐藏自己不想看到的信息；
    - 用途二：**自测**——把收藏变成"填空题"；
    - 补充：提供「全部虚化」一键；**虚化状态需持久化**（否则每次重设）。
- **虚化不算编辑**——只改显示、不改内容，与"内容不可编辑"不冲突。
- **同一条内容反复收藏 → 覆盖**，并给轻提示「已更新这个收藏」（不给提示用户会以为没生效）。
- **导出**：🟡 二期（涉及格式 / 隐私 / 成本）。

### 4.9 考试与教学进度 ✅

#### 4.9.1 考试作为独立实体 ✅

- **Exam**（名称 / 日期 / 科目 / 满分 / 得分）为**独立实体**，不是 Goal 的一种。
- **Goal 引用考试**：挂 `examId` + `targetScore`——避免两套平行的目标体系。
- 关联三处：
  1. 错题可标记「来自某次考试」；
  2. 考后**回填成绩** → 喂状态评估与画像（**客观结果**比自评硬得多，是唯一能把"自评"和"实际"对上的数据）；
  3. 作为 mastery 的校准信号。
- ⚠️ 新实体，需动 `docs/openapi.yaml`。

#### 4.9.2 题本按教学课时顺序排列 ✅

- 题本支持按**知识点所属教学课时**排序。
- 一题涉及多个知识点时：按**涉及知识点数量**，在「单项课时」内**由少到多**排序。
- **一道题可重复出现在不同课时的知识点处**。
- ⚠️ **依赖知识点库的课时 / 顺序字段**——与「知识点库重构」绑定，属**二期依赖**。

### 4.10 学科工具 ✅

#### 4.10.1 入口与形态 ✅

- **触发**：**任意页面**，鼠标悬停**页面上边界** → 一条小黑条滑出 → 单击 → 下拉出菜单。
- **菜单形态**：占据页面上部空间，**左右抵到页面边界**，把原页面内容**"挤"到下面**（下方内容无法完全显示）。
- **菜单内容**：横排卡片。
  - **首卡片 = 学科卡片**：较窄、**彩色**、背景为该学科的**斜置图标**。
    - 鼠标悬停 → 卡片**略浮动放大** + **整个界面虚化（背景模糊）** + 卡片下方**展开全部学科卡片**；
    - 单击某学科 → 该卡片**替换**原学科卡片，**工具集随之切换**。
  - **后续卡片 = 工具卡**：宽度**略大于**学科卡、**深灰色**、带工具名称与图标。
- **单击「学科卡片」本身** → 卡片**扩大至页面居中**、顶栏收起、页面恢复，以**类似浮窗对话**（§3.9）的形式出现**学科工具浮窗**。

> ⚠️ **术语澄清**：此处的"界面虚化"是**背景模糊（景深突出）**，与 §4.8.4 收藏的「虚化」（文本模糊，用于自测 / 隐藏）**是两回事**。为避免混用，正文里后者称「**虚化**」、此处称「**背景模糊**」。

#### 4.10.2 学科与工具的关系 ✅

- 工具集**跟随当前学科**切换（不同学科可有不同工具）。
- **pilot 只做「科学计算器」一个工具**；其余位置保留**占位**，显示"开发中"。

#### 4.10.3 科学计算器浮窗 ✅

- 右上角两个操作：「**添加到对话**」与「✕」。
- **点击「添加到对话」**：
  - 底部页面**切至对话页**；
  - 浮窗消失，变为输入框内的引用块「**科学计算器 ✕**」（与 §3.9 随手问浮窗"添加到主对话"同一形态）；
  - **注入内容 = 本次唤出计算器的全部计算输入与输出**（完整历史，不只是当前显示值）；
  - ⚠️ **最后一个计算若未按「=」/「运算」**，其表达式与结果**也要归拢进去**——因此计算器需维护 `history[]`，**未求值表达式同样入列**。

#### 4.10.4 拍照后的「/题目排序」✅

- **首次**拍照 / 上传照片后，输入框「**+**」按钮出现**光效引导**用户点击（**仅首次**）。
- 「+」内多出「**/题目排序**」，四个子选项：

| 选项 | 说明 |
|---|---|
| **难易排序** | 按题目难度排序 |
| **知识点掌握度排序** | 结合用户 mastery，把自己掌握得差的排前面 |
| **自定义排序** | 用户自己输入排序提示词 |
| **价值遴选** ⭐ | 模型按各题**涉及的知识点**，指出哪些题**知识点 / 解法交叉度高**，按**刷题价值**排序 |

- **适用场景**：用户拍的是**一页题目**（多题）时生效。
- 与 §3.1「自定义常用语（可带前缀）」联动：自定义的排序提示词可**固化为常用语**。

### 4.11 阶段口径：pilot 删档 / beta 起不删档 ✅

- **pilot = 删档测试**：数据可定期清空；schema 可激进调整；**不做**数据导出、迁移与长期存档承诺。
- **beta 起不删档**：需要**稳定的用户 ID 体系**与数据迁移方案。
- ✅ **已定（B 方案）：pilot 期间就引入与登录凭证解耦的稳定 `user_id`**——不等 beta。

**三层身份模型**：

| 层 | 字段 | 能否变 | 用途 |
|---|---|---|---|
| **内部主键** | `users.id` | ❌ **永不变** | 所有业务表外键 |
| **登录凭证** | email / 密码 / 验证码 | ✅ 可改、可换绑 | 仅用于认证，**不作为身份** |
| **对外标识** | handle（可选，用户自设）| ✅ 可改 | 展示用，不暴露邮箱 |

**现状的隐患**：`users.id` 这一列**已经是主键**，但**实际填入的值就是邮箱**——`auth_sessions` 存 email、`get_session()` 返回 email、`routes/user.py` 拿它当 `users.id` 建记录；而 `users` 表**根本没有 email 字段**。所以现在**改邮箱 = 换主键 = 全表外键更新**。

**好消息**：业务表外键**都指向 `users.id`**（不是直接存 email），因此**不需要改表结构**——只需要改"往 `users.id` 里填什么"，并给 `users` 补一个 email 列。改造量比预想小得多。

⏰ **时机**：pilot 是删档期，正是改这个成本最低的时候（数据可丢、直接重建）。详见 [refactor-implementation-notes.md](./refactor-implementation-notes.md)。

## 7. 商业化与付费（订阅 + credits 双模式）✅

**总原则**：规则免费、AI 计费——让用户免费看"状态如何"，为"AI 告诉我怎么办"付费。

**计价 ≠ 计费**：
- 计价（内部）：每个 AI 调用都记账（token/成本）。
- 计费（对用户）：不摊到每个动作，尤其嵌入式 AI 不逐次计。

**三类 AI、两套口径**：

| 类型 | 例子 | 用户感知 | 计费口径 |
|---|---|---|---|
| 对话式 AI | 闲聊/搜题/讲知识点 | 有感、主动发起 | credits / 订阅额度 |
| 嵌入式 AI | 建议/复盘/口语转译/画像提取/推荐卡 | 无感、系统自动 | **不进 credits**，作订阅权益；非订阅走规则模板（降级）|
| 高级 AI | L3 富交互仿真/多模态搜题 | 有感、稀有贵 | 高级月卡+，或 credits 单次 |

**credits**：
- 全功能可用（通用货币），按功能类型定档扣费（不讲 token）。
- 来源：签到送、订阅送、首次订阅送更多——弱化"花钱感"（是"攒"而非"买"）。

**订阅档位（5 档，不连续订阅、统一定价）**：

| 档位 | 定位 | 高级功能 | 送 credits |
|---|---|---|---|
| 周卡 · **Percibir** | 价格锚点（明显不划算）| ✗ | 少量 |
| 基础月卡 · **Attentio** | 相对锚点 | ✗ | 中 |
| 高级月卡 · **Flux** | 主力 | ✓ | 中多 |
| 季卡 · **Emerge** | 折扣 | ✓ | 多 |
| 年卡 · **Maîtrise** | 最大折扣 | ✓ | 最多 |

> 命名递进：感知(Percibir) → 专注(Attentio) → 流动(Flux) → 涌现(Emerge) → 精通(Maîtrise)。

- 所有档位送 credits；新用户首订送更多。
- 高级功能（L3 仿真/多模态）= 高级月卡及以上，或 credits 单次。

**扣费知情与弱化付费感**：
- 单次扣 credits 的动作（搜题/讲解/仿真）前明示"将扣 X credits"；余额不足提示 + 引导订阅/签到。
- 订阅用户**不逐次显示扣费**，走包月额度静默扣。

**待办**：未成年付费（监护人/支付资质）→ 合规暂缓，后续单独立项。

## 8. 数据与埋点 ✅

**方法论**：埋点从「数据消费者」倒推，不为埋而埋；未成年用户，埋点克制 + 目的明确 + 敏感脱敏。

**核心结论**：学习数据大多已有（学习记录/计划/目标/错题/复盘/mastery 均为既有表），真正需新增埋点的仅三块：

1. **Chat 交互**（新形态数据富矿）：
   - 消息事件（role / 意图判定 / 时间戳 / 结构化体，**不含原文流水**）；
   - 卡片事件（展示 / 点击 / 卡内操作 / dismiss）；
   - 意图纠正（模型判 X、实际 Y）；
   - 上下文栈事件（入栈 / 出栈 / 沉降）；
   - 引导式搜题交互（步数 / 打断点 / 续接）。
2. **AI 质量反馈**（反哺迭代）：
   - 建议/讲解/解题的读完率、采纳率、反馈（有用/没用）、纠错；
   - 推荐卡 → 对话 → 完成 的转化链。
3. **画像 trace**（可追溯）：
   - 提取事件（来源消息 / 条目 / 置信度）；
   - 修改/删除事件（用户改哪条）。

> ⚠️ **与对话原文的口径划分**：本节埋点存的是**结构化事件**；消息原文属 §3.8.3 定义的**短期安全留存**（产品不可见、到期删除、不入画像）。二者用途与留存期不同，不可混同。

**数据资产（三张王牌，质量 = 护城河）**：
- 画像：长期、结构化、可追溯、可改可删；
- 状态趋势：时间序列，喂趋势/偏离预警；
- 社区聚合：匿名群体规律，喂 L2–L4。

**原则**：
- 画像可追溯：每个条目能 trace 到「哪次对话提取、为何」。
- 敏感脱敏：聊天文本入库前脱敏（沿用 privacy_filter）。
- 商业埋点（credits 流水/订阅/签到）独立于行为埋点。
