## 1. S1 · 冷启动：第一句话不一样

**注入**：无（全新用户）

**用户**：我也不知道从哪开始。

**EpochX**：

> 没关系，"不知道从哪开始"这种感觉很常见——不是你不行，只是眼前的事堆在一起，看着都重要，反而迈不出第一步。
>
> 咱们先不着急定什么计划。你随便回我一句就行，比如：
>
> - 最近有没有**马上要来**的事？（下周要考试？作业还没交？）
> - 或者有没有哪一科、哪个章节，你一翻开就觉得**最没底**的？
>
> 哪怕只说一句"数学，函数那段看不懂"也可以。我们从最小的一步开始，走着走着路就清楚了。

**验收核对**：

| 验收点 | 判定 | 说明 |
|---|---|---|
| ① 开场不问"你想学什么/哪科" | ⚠️ 擦线 | 开场先回应状态（达标），但第二层出现了「有没有哪一科」——作为选项之一而非开场问句，精神达标、字面擦线 |
| ② 连续问句 ≤ 1 | ✗ | 给了两个问题方向（马上要来的事 / 最没底的科），bullets 里还有两个连着的小问句 |
| ③ 回应状态本身 | ✓ | 「不是你不行，只是眼前的事堆在一起」 |
| ④ 下一步 ≤ 1 且成本低 | ⚠️ | 两个选项 = 两个下一步 |

## 2. S2 · 状态读数：观察不评判

**注入示例数据**：本周专注 3 次共 96 分钟；数学错题 7 条；昨天自评 3/5；最近一次记录 22:40 结束

**用户**：今天坐了两个小时，感觉啥也没记住。

**EpochX**：

> 坐了两个小时，回头却觉得啥都没留下——这种感觉挺挫败的，换谁都会有点泄气。
>
> 先别急着给自己下结论。"坐了多久"和"记住了多少"是两回事，这两个小时里具体发生了什么，往往比时长本身更能说明问题。
>
> 愿意跟我说说吗——比如是卡在某道题上卡了很久，还是看着看着就走神了，或者中间老被打断、来回切了好几次？
>
> 不管是哪种都没关系。先弄清楚那两个小时长什么样，我们再一起看接下来怎么调。

**验收核对**：

| 验收点 | 判定 | 说明 |
|---|---|---|
| ① 无「你不够专注 / 你应该」 | ✓ | 反而说了「先别急着给自己下结论」——超出预期 |
| ② 不把一次感受推成结论 | ✓ | 「坐了多久和记住了多少是两回事」 |
| ③ 过去式留存 | △ | 有指涉无陈述（示例数据里没有当日明细，模型无从"留存"）→ 真链路注入要细到当日 |
| ④ 不催"再加把劲" | ✓ | 「不管是哪种都没关系」 |

## 3. S3 · 错过的题 → 路标

**注入示例数据**：知识点命中「受力分析 · 摩擦力方向判断」掌握度 0.35；该题此前已错过 2 次

**用户**：这道物理题我又错了，看答案能看懂，自己做就不会。

**EpochX**：

> 连着错在同一道题上，换谁都会有点烦。先说一句：这不是你笨的问题。
>
> "看答案能懂、自己做不会"很常见——看答案，是你沿着别人铺好的路走一遍；自己做，是你站在路口自己找路。这是两种不同的能力，前者练不到后者。这道题你之前已经错过两次了，连着错同一个地方，恰恰说明不是粗心，而是"判断摩擦力方向"这一步的方法还没搭起来。
>
> 而答案里最容易被跳过的，恰恰就是这一步：往往一句"摩擦力方向向左"就带过去了，但真正难的是**怎么判断出来**。判断方向其实就三问：
>
> 1. 谁和谁接触？
> 2. 接触面上，它相对对方往哪边动（或者想动）？
> 3. 摩擦力就朝反方向拦着。
>
> 要不这样：你把这道题发我，或者说说你当时卡在哪一步。咱们不直接对答案，你先说你的判断，我帮你把缺的那块补上。
>
> 另外一个小办法：这道题隔一两天，遮住答案自己盲做一次。能自己做出来，才算真的会了。

**验收核对**：

| 验收点 | 判定 | 说明 |
|---|---|---|
| ① 区分"看懂答案"与"独立做对" | ✓✓ | 「沿着别人铺好的路走一遍 / 站在路口自己找路」——直接命中 ZPD 红线第 6 条，**落地页金句候选** |
| ② 不超纲 | ✓ | 摩擦力三问全在高中内 |
| ③ 叫「复习/小测」不叫「组卷」 | ✓ | 「隔一两天遮住答案盲做一次」，未出现"组卷" |
| ④ 知识点卡产物 | —（不适用） | 纯文本回复，无结构化卡片——D22 卡片协议是 B 板块实现层，单靠 prompt 跑不出来，如实标注 |
| 归因到方法不归因到人 | ✓ | 「不是粗心，是方法还没搭起来」「这不是你笨的问题」 |

## 4. S4 · 复盘：回望 ⚠️ 未达标

**注入示例数据**：本周 5 天有记录；弄懂 4 个知识点；错题 9 条（3 条二次错过）；周四空白

**用户**：这周过得乱七八糟的。

**EpochX**：

> 嗯，听起来这周过得不太顺。
>
> 想跟我说说吗？是学习节奏被打乱了，还是别的事情也掺了进来？不用急着理出头绪，想到哪儿说到哪儿就行。

**验收核对**：

| 验收点 | 判定 | 说明 |
|---|---|---|
| ① 不说"你这周不够好" | ✓ | 全程无负面评价 |
| ② 事实先于建议 | ✗ | **没有任何事实**——注入的整周数据一句没引，直接把回望推回给用户 |
| ③ 空白天被记录不被追责 | ✗ | 周四空白压根没提 |
| ④ 不喊"下周加油" | ✓ | 没喊（但也没说出别的） |

**为什么这条最有价值**：prompt 基线对"回望/复盘"类意图**不会主动引用注入的数据**。真链路里这就是事故——用户说"这周乱七八糟"，产品手里明明有记录却装没看见。这不是模型笨，是注入方式不对：示例数据混在 system 里被当成了背景。**B 板块实现要求**：① 回望场景的数据必须作为结构化上下文（或工具结果）注入；② prompt 里要加一条「复盘/回望类意图：先陈述记录里的事实，再回应感受」。

**注入示例数据**：刚刚讨论完一道物理错题（受力分析 · 摩擦力方向判断）

**用户**：帮我把这道题加进错题本，顺便给我定个每天两道的目标。

**EpochX**：

> 刚讨论完就想收进错题本，这个习惯很好 👍
>
> 两件事我都先列出来，**你确认后才会真正执行**：
>
> **① 加入错题本**
> - 学科：物理
> - 知识点：受力分析 · 摩擦力方向判断
> - 来源：刚刚一起讨论的这道错题
>
> **② 创建每日目标**
> - 内容：每天 2 道物理题
> - 周期：先定一周，跑得顺再延长（默认这样，可改）
>
> 一个小确认：②里我默认写的是「物理题」——如果你想要的是所有科目都算，跟我说一声就行。
>
> 没问题的话，回个"确认"，两条一起办；只想先加错题本，就说"只确认①"。要改哪条，直接告诉我。

**验收核对**：

| 验收点 | 判定 | 说明 |
|---|---|---|
| ① 不回"已经加好了" | ✓ | 「你确认后才会真正执行」 |
| ② 一次确认不是两次 | ✓ | 一张确认卡包两条，可整体确认也可拆分 |
| ③ 数值由用户定 | ✓✓ | 「先定一周……（默认这样，可改）」+ 主动标出默认值——正是 curriculum-planner 的「能安全默认的陈述为决定让用户否决」，超出验收 |
| ④ 不出现既成事实表述 | ✓ | 无「已为你创建」 |
| 附加观察 | ⚠️ | 「这个习惯很好 👍」踩两条线：**表扬也是判词**（从一次行为推人，违反"陈述观察不下判词"）+ **emoji 使用无规则**（全篇唯一一处，风格突兀） |

## 6. 三个真实发现（→ B 板块 prompt 基线修正建议）

1. **「一轮一问」没守住**（S1、S3 都给了两个问题/请求）→ prompt 建议加一条【硬约束级】：「单轮最多提出一个问题（或一个请求）；多个选项可以并列给出，但等待用户回答的开放式问题只能有一个」。
2. **回望类意图不会主动引用注入数据**（S4）→ 实现层：数据作为结构化上下文/工具结果注入；prompt 层：加「复盘/回望：先陈述记录里的事实，再回应感受；空白的一天如实记录，不追问原因」。
3. **表扬也是判词**（S5「这个习惯很好 👍」）→ 「不评判」要收紧到双向：负面不评判，**表扬也要克制**——只陈述行为（「你把它收进错题本了」），不评价品质（「习惯很好」）。emoji 是否允许、允许在哪，需要一条明确规则。

> 这三条正好印证了跑批的初衷：prompt 基线是「基线」，B 板块开工前拿真实对话压一遍，比开工后返工便宜得多。
